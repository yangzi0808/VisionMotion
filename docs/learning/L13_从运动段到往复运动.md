### 4.3 `detect_turning_points()` 的职责边界（第 462–593 行）

`src\dynamic_displacement.py` 第 462–593 行的 `detect_turning_points()` 只做两件事：

1. 用原始 `x_px` 序列 + 20 px 反向行程规则找**转向点**；
2. 用转向点把序列切成**运动段**。

它的返回值里只有 `turns` 与 `segments` 这两层结构（另有起点 / 终点、分析行数等报告字段），
**没有**任何"相邻转向点时间间隔""半周期""周期 T""频率 f""周期稳定性判据"字段。

调用点在 `build_ds_from_track_csv()` 第 1183 行（`"turning": detect_turning_points(rows)`），
即：转向点 / 运动段是在生成 ds 报告时一次性算出的，算完之后没有被进一步拿去做时间间隔统计。

### 4.4 `turns` 的七个字段（第 540–563 行，项目真实源码）

`turns` 由 `describe()`（第 540–547 行）与组装循环（第 552–563 行）共同生成，每条记录有七个字段：

| 字段 | 来源行 | 含义 |
| --- | --- | --- |
| `frame` | 第 543 行 | 转向点所在帧号（存的是**极值帧**，不是确认帧，见 L12） |
| `time_s` | 第 544 行 | 该帧对应的时间（秒）——**L13 的时间分析就靠这一列** |
| `x_px` | 第 545 行 | 该帧的原始水平像素位置 |
| `ds_mm` | 第 546 行 | 该帧的毫米位移；`valid=False` 时为 `None`（打印"无"，不伪造数值） |

1. `time_s` 是**测量链里已经存在的真实时间戳**（由视频帧率决定，不是 L13 新造的）；
2. `kind` 让每个时间戳都带上**事件类型**：这条时间戳是峰，还是谷。

`time_s` + `kind` 合在一起，就已经构成一条**事件序列**——这正是 L13 可以开始讨论"重复"的原因（见第 6 节）。

## 6. 【概念解释】turns 为什么能帮助时间分析

L12 结束时，`turns` 里每条记录都同时带着：

- **时间戳**：`time_s`（第 544 行）；
- **事件类型**：`kind`（peak / valley，第 555 行）；
- **相关位置**：`x_px` / `ds_mm`（第 545–546 行）。

因此 turns 做了一件关键的事：**把连续运动转化为带时间戳、带事件类型的事件序列**。

连续信号（每秒 30 个采样点）本身不容易直接回答"重复了几次、每次隔多久"；
而事件序列把问题变成了离散的、可以两两相减的问题：

```text
peak   f491  t = 8.166327 s
valley f602  t = 10.012483 s
peak   f838  t = 13.937642 s
valley f1063 t = 17.679849 s
peak   f1254 t = 20.856567 s
valley f1513 t = 25.164263 s
```

（上表数字是 EXP-004 的真实数据，见第 11 节。）
有了这张表，**"两次转向之间隔了多少秒"就变成一个简单的减法问题**：后一个事件的 `time_s` 减去前一个事件的 `time_s`。

这是 L13 的全部立足点：**turns 提供时间戳，间隔分析才有可能开始**——而间隔分析正是"周期 / 频率"的前置条件。

## 7. 【概念解释】segments 的用途

`segments` 提供的是**每个单方向运动区间的完整描述**：

- 这一段从哪一帧 / 哪一秒开始，到哪一帧 / 哪一秒结束（`start_*` / `end_*`）；
- 这一段朝哪个方向运动（`direction`）；
- 这一段走了多远（`travel_px`）；
- 这一段是否小于 20 px（`below_min_travel`）。

它的用途是回答："**每半个来回，具体是怎么走的？**"

例如 EXP-004 的 7 个运动段（L12 已核对）：

```text
段1 f0    → f491  正向 205.05 px
段2 f491  → f602  负向  84.80 px
段3 f602  → f838  正向 126.17 px
段4 f838  → f1063 负向  92.22 px
段5 f1063 → f1254 正向 190.09 px
段6 f1254 → f1513 负向 128.80 px
段7 f1513 → f1765 正向 188.61 px
```

但请注意：**segments 描述的是"怎么走"，不是"周期是多少"**。
段的时长（例如段3 f602→f838 约 3.93 s）只是一个**半周期候选**的原始素材，
还不能直接当作周期，也不能单独当作"可靠的半周期"（见第 8、9 节）。

## 8. 【概念解释】一个运动段 ≠ 一个周期

这是本课最重要的概念区分。理由有三条：

### 8.1 首尾段可能被视频边界截断

`detect_turning_points()` 的 docstring 第 478–479 行明确：视频首帧与末帧不是极值点，只作为记录边界（起点 / 终点）。
因此：

- 第 1 段（EXP-004：f0 → f491）的起点是**视频开头**，不是上一个峰 / 谷；
- 最后一段（EXP-004：f1513 → f1765）的终点是**视频结尾**，不是下一个峰 / 谷。

这两段的时间长度**不能**当作完整的半周期样本：我们不知道视频开始之前运动已经走了多久，也不知道视频结束之后还会走多久。

### 8.2 一个 segment 只代表一个方向

每个 segment 的 `direction` 只有一种取值（正向 / 负向 / 无位移，第 572–577 行）。
也就是说，一个 segment 只是"一个来"或"一个回"，**最多只能算半个来回**。

### 8.3 周期应由同类事件之间定义

"一个完整周期"在往复运动里指的是：**运动状态回到同一种状态**。
因此：

- 用 **peak→peak** 或 **valley→valley**（同类事件）定义完整周期；
- 用 **peak→valley** 或 **valley→peak**（异类相邻事件）定义半周期候选。

按"段"来数（段边界 = 起点 + 转向点 + 终点，第 566 行）并不能保证"同类事件"——段与段之间是交替方向的，
更不能用"某一段 + 它后面随便一段"凑一个周期。

## 9. 【概念解释】半周期与完整周期（四类事件间隔）

在 turns 的事件序列上，间隔按**事件类型**分成四类：

| 间隔类型 | 例子（EXP-004） | 本课定位 |
| --- | --- | --- |
| peak → valley | f491 → f602（1.846156 s） | **半周期候选** |
| valley → peak | f602 → f838（3.925159 s） | **半周期候选** |
| peak → peak | f491 → f838（5.771315 s）；f838 → f1254（6.918925 s） | **完整周期候选** |
| valley → valley | f602 → f1063（7.667366 s）；f1063 → f1513（7.484414 s） | **完整周期候选** |

（数字来源与完整统计见第 11 节。）

两条纪律：

1. **半周期候选只能从相邻的异类事件取**（peak 隔壁是 valley、valley 隔壁是 peak）；
2. **完整周期候选只能从同类事件之间取**（峰对峰、谷对谷），且应当检查"半周期的两倍"与"整周期"是否彼此接近。

注意用词：这里说的是"候选"（candidate），不是"结论"。
候选要经过一致性检查（第 10 节）之后，才有资格被称为"一个可信的周期值"。

## 10. 【概念解释】周期成立的基本思想：先证明"重复得足够一致"

看到几个峰谷，只能说明"出现了往复结构"；要谈"周期"，还必须检查**间隔是否足够一致**：

1. **同类事件的间隔**：peak→peak、valley→valley 的各个间隔彼此接近吗？
2. **半周期与完整周期是否一致**：2 × 半周期均值 ≈ 完整周期均值吗？
3. **样本数量**：我们手里只有 2 个 peak→peak 间隔、2 个 valley→valley 间隔，这么少的样本能支持多强的结论？
4. **数据一致性**：所有间隔是否来自同一段连续、无大缺口、检测可信的数据？

四条检查缺一不可。只有四条都通过，"周期值"才值得信任。

这就是本课的核心思想：

> **先证明重复，再谈周期；先证明周期稳定，再谈频率。**

不要看到几个峰谷就直接宣布一个周期。必须看：

- 同类事件的间隔；
- 半周期与完整周期是否一致；
- 样本数量；
- 数据一致性。

- 半周期候选：0.40 / 0.60 / 1.10 / 0.90 s —— 相差超过一倍；
- 完整周期候选（peak→peak）：1.00 / 2.00 s —— 相差一倍；
- 这种数据只能说"发生了往复运动"，**不能**给出一个可信的周期值。

两个示例合起来说明：**峰谷的出现只证明"往复"，间隔的一致才决定"周期"。**

## 14. 【概念伪代码】事件间隔统计与一致性检查（不是项目源码）

> **概念伪代码**：下面这段用来表达"间隔统计 + 一致性检查"的流程思想，
> **不是 VisionMotion 真实源码**；当前项目里没有这段代码，L13 也不写、不运行、不落地任何实现。

```python
# 概念伪代码：事件间隔统计与一致性检查（非项目源码）

# 输入：turns（每个事件带 time_s 与 kind）

# 1. 逐个事件算出"相邻事件间隔"（半周期候选的原始素材）
neighbor_intervals = []
for 前一个事件, 后一个事件 in turns 的相邻对:
    neighbor_intervals.append(后一个事件.time_s - 前一个事件.time_s)

# 2. 按事件类型提取同类间隔（完整周期候选）
#    同类事件之间隔着一个事件：peak → valley → peak，因此要跨两步配对
peak_to_peak = []
valley_to_valley = []
for i in range(len(turns) - 2):
    起点, 中间事件, 终点 = turns[i], turns[i + 1], turns[i + 2]
    if 起点.kind == "peak" and 终点.kind == "peak":
        peak_to_peak.append(终点.time_s - 起点.time_s)
    if 起点.kind == "valley" and 终点.kind == "valley":
        valley_to_valley.append(终点.time_s - 起点.time_s)

# 3. 统计
半周期均值 = mean(neighbor_intervals)
峰对峰均值 = mean(peak_to_peak)
谷对谷均值 = mean(valley_to_valley)

# 4. 一致性检查（本课的思想，不是已实现功能）
if len(peak_to_peak) < 3 or len(valley_to_valley) < 3:
    结论 = "样本太少，不能给出正式周期值"
elif max(neighbor_intervals) / min(neighbor_intervals) > 1.5:
    结论 = "半周期候选不一致，不能给出正式周期值"
elif 峰对峰均值 与 2 × 半周期均值 的差 > 10%:
    结论 = "完整周期与半周期不自洽，不能给出正式周期值"
else:
    结论 = "可以讨论一个候选周期值（仍需数据一致性检查）"

# 5. 频率只在周期被证明稳定之后才谈：
#    频率 = 1 / 周期
```

说明：

- 上面出现的 1.5 倍、10%、3 个样本等数字**只是教学用的示意阈值**，不是项目冻结常量，也不是本课给出的正式判据；
- 伪代码里"两个相邻间隔组成一个 peak→peak"的细节，正是下一课要真正处理的问题；
- 本课只建立**思想**：先做间隔统计，再做一致性检查，最后才谈周期与频率。

## 15. 【本课思想】先证明重复，再谈周期；先证明周期稳定，再谈频率

> **本课核心思想**：
>
> **"先证明重复，再谈周期；先证明周期稳定，再谈频率。"**

展开成操作顺序：

1. **重复**：同类事件（peak / valley）反复出现 → 说明存在往复结构；
2. **间隔**：把同类事件两两配对，算出间隔；
3. **一致性**：间隔彼此足够接近、半周期与完整周期互相自洽、样本数量足够；
4. **周期**：以上都通过，才可以给出一个候选周期值；
5. **频率**：周期值被证明稳定之后，才谈频率。

不要看到几个峰谷就直接宣布一个周期。必须看：

- 同类事件的间隔；
- 半周期与完整周期是否一致；
- 样本数量；
- 数据一致性。
