## 1. L19 学习目标

学完本节课，应该能够：

- 说出为什么"视频是离散采样"：30 fps 的视频每秒只有 30 个采样时刻，每帧只给出一次 y0 测量，真实的连续运动从未被直接观测；
- 背下 M6 的真实采样参数：**N = 160、frame 76–235、fs = 30 Hz、dt = 1/30 s ≈ 0.033333 s、T_record = 5.3333 s**，并能说出各个数字的出处（源码、报告、CSV）；
- 说出频率格点公式：**df = fs / N**、**f_k = k · df**；M6 口径下 df = 30 / 160 = 0.1875 Hz；
- 说出 **1.875 Hz = 10 × 0.1875 Hz（k = 10）**，恰好落在格点上；**1.843003 Hz 位于格点之间**，最近的格点是 k = 10（1.875 Hz），距离 0.031997 Hz；
- 解释 **df ≈ 1 / T_record** 的含义：格点间距由记录长度决定，记录越长、格点越密、频率分辨越细；
- 复述频谱泄漏的四个要素：**有限记录 → 非整数周期截断 → 边界不连续 → 能量扩散到邻近频率格点**；
- 用自己的话讲清本课两个教学示例（1.875 Hz 整周期示例 / 1.900 Hz 非整周期泄漏示例），并能主动声明它们是"**教学示例，不是项目数据，不是项目代码**"；
- 说出窗函数（矩形窗、Hann、Hamming、Blackman）在做什么：压低旁瓣、减弱泄漏的代价是主瓣变宽、分辨能力下降；**"加窗不一定更准确，而是权衡"**；
- 说出 zero padding 的边界：**输出格点变密，但不增加真实观测时间、不增加原始信息**；
- 背下当前工程边界：`src\` / `demo\` **无运行时 FFT、无实际频谱数组、无窗口函数、无 zero padding、无 detrend、无重采样**；`src\m63_final_visualization.py` 第 119–120 行只是冻结值；`src\m73_presentation.py` 第 423 行的 rFFT 只是 PPT 文字；
- 复述 M6 频域对照结论：f_exp = 1.843003 Hz、f_FFT = 1.875 Hz、差值 0.031997 Hz、相对差 1.74%、半格 0.09375 Hz；**FFT 是独立交叉验证，不替代时域峰—峰周期测量**。

## 4. 【概念解释】视频采样：连续世界的离散切片

- 视频不是"连续信号"，而是以固定时间间隔拍摄的离散帧序列；M6 视频为 **30 fps**，即每秒 30 帧；
- 每 1/30 s 拍摄一帧，每一帧经过 L16 的提取流程给出一次数值测量（y0 位置），因此 y0(t) 只在 t = frame / 30 这些**离散时刻**存在采样值；
- **采样间隔** dt = 1/30 s ≈ 0.033333 s；**采样率** fs = 30 Hz。连续运动在两次采样之间的行为没有被观测到；
- 采样带来两条直接后果：
  1. 时间分辨率有限：极值时刻只能定位到帧格点上。M6 报告用"±0.5 frame 假设下 δT_sampling ≈ 0.0333 s"作为保守采样定位上界（报告第 253 行；同一数值冻结在 `src\m63_final_visualization.py` 第 117 行 `dT_sampling = 0.0333`）；
  2. 可无歧义表达的最高频率受奈奎斯特频率 fs / 2 = 15 Hz 限制（一般理论；L18 已登记）。M6 主频约 1.84 Hz，远低于 15 Hz，因此主振动成分在时间采样上远离混叠风险。
- 一句话：**y0(t) 是从视频采样得到的时间序列，不是对连续运动的直接观测**。

## 6. 【概念解释】频率格点：FFT 只能回答"格点上"的频率

- FFT 的输出不是一条可以任意取值的连续频率曲线，而是**离散频率格点**上的数值：f_k = k · df，其中 df = fs / N；
- M6 数据口径下的核对计算（一般理论 / 核对算术，不是源码实现）：
  - df = fs / N = 30 / 160 = **0.1875 Hz**；
  - 实数信号的单边频率格点：k = 0, 1, 2, …, 80，对应 0 Hz, 0.1875 Hz, 0.375 Hz, …, 15 Hz（奈奎斯特频率处为 k = 80）；
  - **1.875 Hz = 10 × 0.1875 Hz，正好是 k = 10 号格点**；
  - **1.843003 Hz 位于格点之间**：它不是 0.1875 的整数倍（1.843003 / 0.1875 ≈ 9.83），落在 k = 9（1.6875 Hz）与 k = 10（1.875 Hz）之间，最近格点是 k = 10；
  - 1.843003 Hz 到最近格点的距离 = 1.875 − 1.843003 = **0.031997 Hz**（小于半格 0.09375 Hz）。
- 因此 FFT 报告出来的主峰只能是**最近的格点读数**；1.875 Hz 应理解为"1.843003 Hz 附近那条谱线落在 k = 10 上"，而不是"FFT 更精确地测到了 1.875 Hz"。

## 7. 【概念解释】df ≈ 1 / T_record 的含义

- 由定义直接可得：df = fs / N = 1 / (N / fs) = 1 / T_record；
- 直观含义：**观测时长决定频率格点的疏密**。记录越长，df 越小，格点越密，能区分开的频率差越小；
- 另一种说法：频率相差 Δf 的两个成分，需要至少约 1 / Δf 的观测时间才可能被区分开；
- M6 核对：T_record = 5.3333 s → df = 1 / 5.3333 ≈ 0.1875 Hz，与 fs / N 的计算一致；
- 注意：这里说的是"这条记录能分辨的最小频率间隔"，不是"FFT 算法本身的精度极限"；两条不同长度的记录对同一物理过程可能给出不同的 df。

## 8. 【概念解释】频谱泄漏：有限记录 + 非整数周期截断

把一段有限长信号交给 FFT，数学上隐含了一个假设：**这段记录会以 T_record 为周期无限重复下去**。频谱泄漏就来自这个假设与真实信号之间的错位，四个要素是：

1. **有限记录**：我们只有 frame 76–235（5.3333 s）这一段，不是无限长的振动信号；
2. **非整数周期截断**：记录内包含的周期数不是整数。M6 主频 1.843003 Hz 在 5.3333 s 的记录内约含 9.83 个周期（核对算术：1.843003 × 5.3333 ≈ 9.83），不是整数；
3. **边界不连续**：把这段记录首尾相接、按周期重复时，起点与终点对不上，出现跳变；跳变在频域表现为宽带成分；
4. **能量扩散到邻近频率格点**：真实频率的能量没有被收进单一格点，而是"漏"到邻近格点上——这就是频谱泄漏。峰值仍然出现在**最近的格点**（k = 10 = 1.875 Hz），但旁边的格点也被抬起。

要强调的两点：

- **泄漏不是数据错误**，而是"有限记录 + 非整数周期"带来的系统性效应；真实视频里几乎不可能恰好整周期截断（真实频率未知，也不会刚好是 df 的整数倍）；
- 1.843003 Hz 位于格点之间（第 6 节），本身就不可能被单一格点精确表达；FFT 主峰落在最近的格点 1.875 Hz 上，是"格点化读数"，不是频率发生了漂移。

**【教学示例】特别声明：本节两个频率（1.875 Hz 与 1.900 Hz）是为了讲解"整周期 vs 非整周期"而设定的教学示例，不是 VisionMotion 项目数据，不是项目代码，也不是本课运行出来的结果。** 项目真实现象见第 12 节（f_exp = 1.843003 Hz、f_FFT = 1.875 Hz）。

## 10. 【概念解释】窗函数：压低旁瓣的代价是主瓣变宽

- **矩形窗**：截取一段记录本身 = 隐式乘上一个矩形窗；矩形窗主瓣最窄，但旁瓣较高，泄漏相对明显；
- **Hann / Hamming / Blackman 等窗**：两端平滑渐变为 0，让记录边界处的幅度压低，减小首尾跳变 → 旁瓣被压低 → 泄漏减弱；
- 代价：**主瓣变宽**，相邻频率成分更难分开（频率分辨能力下降）；不同窗在主瓣宽度与旁瓣高度之间有不同折中；
- 因此结论是：**加窗不一定更准确，而是权衡**——它改变的是"泄漏分布"的取舍，不会凭空增加记录长度带来的信息；
- 项目事实边界：M6.3 封板 FFT 的做法是"不加窗"（`docs\M6.3_FINAL_REPORT.md` 第 175 行），当前 `src\` / `demo\` 也没有任何窗函数实现（第 3.3 节）。窗函数是本课的概念工具。

## 11. 【概念解释】Zero Padding：格点变密 ≠ 信息变多

- zero padding 的概念做法：在有限记录末尾补上一串零，再做 FFT；
- 效果：输出频率格点变密（补到 N_pad 点后，格点间距约为 fs / N_pad），频谱曲线看起来更"光滑"，便于读峰；
- 但它**不增加真实观测时间**（物理观测仍然只有 5.3333 s），**不增加原始信息**；真实分辨能力仍由 T_record 决定，不能靠补零区分两个本来就分不开的频率；
- 项目事实边界：M6.3 封板 FFT 的做法是"不补零"（`docs\M6.3_FINAL_REPORT.md` 第 175 行），当前 `src\` / `demo\` 也没有 `np.pad` / 补零实现（第 3.4 节）。

## 14. 本课核心知识链

**视频帧序列（30 fps 离散采样）→ 有限记录（frame 76–235，N = 160，T_record = 5.3333 s）→ FFT 只能输出 k · df 固定格点（df = 0.1875 Hz = 1 / T_record）→ 真实频率 1.843003 Hz 位于格点之间（记录内约 9.83 个周期，非整数）→ 周期延拓边界不连续 → 频谱泄漏（能量扩散到邻近格点）→ 主峰被格点化到最近的 k = 10（1.875 Hz）→ 加窗是"旁瓣 vs 主瓣"的权衡、补零只加密格点不增加信息 → 结论：FFT 的 1.875 Hz 是对时域 1.843003 Hz 的独立频域交叉验证，不是更"正确"的频率。**

一句话记忆：**先有采样和记录长度，才有格点和泄漏；没有这两步，就没有"1.875 与 1.843003"的全部讨论。**

**Q6：加窗一定让结果更准确吗？**

标准答案：不一定。Hann / Hamming / Blackman 等窗压低旁瓣、减弱泄漏，但主瓣变宽、频率分辨能力下降——是权衡，不是免费提升。矩形窗（截断本身）主瓣最窄但旁瓣较高。加窗不一定更准确，而是权衡。M6.3 封板做法是"不加窗"（报告第 175 行）。

**Q7：zero padding 能提高频率分辨率吗？**

标准答案：不能。zero padding 只让输出频率格点变密、曲线更便于读峰，但不增加真实观测时间（仍是 5.3333 s），不增加原始信息；真实分辨能力仍由 T_record 决定。M6.3 封板做法是"不补零"（报告第 175 行）。

**Q8：M6 里 FFT 的角色是什么？为什么不能说 1.875 Hz 比 1.843003 Hz 更正确？**

标准答案：FFT 是**独立的频域交叉验证**，不替代时域峰—峰周期测量，中心频率取自时域（报告第 185 行）。差值 |Δf| = 0.031997 Hz（相对差 1.74%）小于半格 0.09375 Hz，说明两者在分辨率范围内一致（报告第 186 行）；1.875 Hz 是格点系统里的就近读数，不能视为更"正确"。
