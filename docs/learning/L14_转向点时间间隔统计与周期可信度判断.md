### 4.3 `detect_turning_points()` 的职责边界（第 491–622 行）

`src\dynamic_displacement.py` 第 491–622 行的 `detect_turning_points()` 只做两件事：

1. 用原始 `x_px` 序列 + 20 px 反向行程规则找**转向点**（`turn_indexes`，第 542–567 行）；
2. 用转向点把序列切成**运动段**（第 594–620 行）。

它的返回值里只有 `turns` 与 `segments` 这两层结构（另有起点 / 终点、分析行数等报告字段），
**没有**任何"相邻转向点时间间隔""半周期""周期 T""频率 f""周期一致性判据"字段。

调用点在 `build_ds_from_track_csv()` 第 1218 行（`"turning": detect_turning_points(rows)`），
即：转向点 / 运动段是在生成 ds 报告时一次性算出的，算完之后没有被进一步拿去做时间间隔统计。

### 4.5 turns 的组装（第 581–592 行，项目真实源码）

turns 由 `describe()` 与组装循环共同生成：先取 `describe()` 的四个字段（第 582–583 行），再加上：

- `kind`（第 584 行）：`"peak"` 或 `"valley"`；
- `direction_before`（第 585–587 / 588–590 行）：转向前的方向（由 `kind` 推导）；
- `direction_after`（第 585–587 / 588–590 行）：转向后的方向（由 `kind` 推导）。

因此 turns 的每条记录有**七个字段**：`frame` / `time_s` / `x_px` / `ds_mm` / `kind` / `direction_before` / `direction_after`。

### 4.6 segments 的组装（第 594–620 行，项目真实源码）

segments 由第 594–620 行生成，每段的字段为：

- `start_frame` / `start_time_s` / `start_x_px`（第 609–611 行）
- `end_frame` / `end_time_s` / `end_x_px`（第 612–614 行）
- `direction`（第 615 行；由两端 x 的大小关系决定，第 601–606 行）
- `travel_px`（第 600、616 行；`abs(tail["x_px"] - head["x_px"])`）

边界由 `boundary_indexes`（第 595 行）给出：`[起点] + [各转向点] + [终点]`；
docstring 第 507–508 行明确"首帧与末帧不是极值点，只作为记录边界；运动段数 = 转向点数量 + 1"。

注意：段的 `start_time_s` / `end_time_s` 当然可以相减得到"这一段用了多少秒"，
但**当前源码没有做这个减法**，也没有把它写成任何字段；"段时长"只是数据本身蕴含的信息，不是已实现的功能。

## 5. 【概念伪代码】从 turns 到时间间隔（不是项目源码）

> **概念伪代码**：下面这段用来表达"从 turns 到时间间隔"的流程思想，
> **不是 VisionMotion 真实源码**；当前项目里没有这段代码，L14 也不写、不运行、不落地任何实现。

流程一共五步：

1. 按 `kind` 把 turns 分成 **peaks / valleys** 两组；
2. **相邻 peak 做 `time_s` 相减**（峰—峰间隔）；
3. **相邻 valley 做 `time_s` 相减**（谷—谷间隔）；
4. **相邻 peak/valley 交替事件做 `time_s` 相减**（所有相邻事件对，峰—谷交替）；
5. 得到两类结果：
   - **完整周期候选**：peak→peak、valley→valley；
   - **半周期候选**：peak→valley、valley→peak。

```python
# 概念伪代码：从 turns 到时间间隔（非项目源码）

# 输入：turns（每个事件带 time_s 与 kind，例如第 569–592 行产出的记录）

# 1. 按 kind 分成两组
peaks = [事件 for 事件 in turns if 事件.kind == "peak"]
valleys = [事件 for 事件 in turns if 事件.kind == "valley"]

# 2. 相邻 peak 相减（同类）
peak_to_peak = [
    peaks[i + 1].time_s - peaks[i].time_s
    for i in range(len(peaks) - 1)
]

# 3. 相邻 valley 相减（同类）
valley_to_valley = [
    valleys[i + 1].time_s - valleys[i].time_s
    for i in range(len(valleys) - 1)
]

# 4. 相邻 peak / valley 交替事件相减（异类，成对出现）
neighbor_intervals = [
    turns[i + 1].time_s - turns[i].time_s
    for i in range(len(turns) - 1)
]

# 5. 得到两类结果
#    - 完整周期候选：peak_to_peak、valley_to_valley
#    - 半周期候选：neighbor_intervals（由 peak→valley / valley→peak 交替组成）
```

三点说明：

- 上面这段是**概念分析**，不是当前 VisionMotion 已存在的代码；
- 第 4 步的"所有相邻事件间隔"里既有 peak→valley 也有 valley→peak，必须用 `kind` 检查两端类型才能分类（本课不展开边界情形的处理）；
- 本课产出的是"候选"与"统计量"，**不是"已经宣布的周期值"**——是否可信还要过第 9 节的四步框架。

## 6. 【概念解释】半周期与完整周期

### 6.1 四类事件间隔

| 间隔类型 | 两端事件 | 运动学含义 | 本课定位 |
| --- | --- | --- | --- |
| peak → valley | 峰 → 谷 | 从一个极点走到另一个极点 | **半周期候选** |
| valley → peak | 谷 → 峰 | 从另一个极点走回 | **半周期候选** |
| peak → peak | 峰 → 峰 | 跨两次转向（峰 → 谷 → 峰） | **完整周期候选** |
| valley → valley | 谷 → 谷 | 跨两次转向（谷 → 峰 → 谷） | **完整周期候选** |

两条纪律：

1. **半周期候选只能从相邻的异类事件取**（peak 隔壁是 valley、valley 隔壁是 peak）；
2. **完整周期候选只能从同类事件之间取**（峰对峰、谷对谷），且应当检查"半周期的两倍"与"完整周期"是否彼此接近。

注意用词：这里说的是"候选"（candidate），不是"结论"。候选要经过第 9 节的四步检查之后，才有资格被称为"一个可信的周期值"。

### 6.2 一个运动段 ≠ 一个周期

L12 切出来的每个 `segment` 都是一个**单方向**的运动区间；它不能直接当作一个周期。三条理由：

1. **首尾段可能被视频边界截断**：`detect_turning_points()` docstring 第 507–508 行明确"视频首帧与末帧不是极值点，只作为记录边界"；EXP-004 的段 1（f0 → f491）与段 7（f1513 → f1765）各有一端是视频边界——我们不知道视频开始之前 / 结束之后运动已经走了多久，无法保证"从极值到极值"是完整的一半；
2. **一个运动段只表示一个方向**：段的 `direction` 只有一种取值（第 601–606、615 行），最多是"半个来回"；
3. **周期应由同类事件之间的时间间隔定义**：只有 peak→peak / valley→valley 才是"完整来回一次要多久"的候选；段的边界是"起点 + 转向点 + 终点"（`boundary_indexes`，第 595 行），不是同类事件。

一句话：**段描述"这一程怎么走"，周期描述"完整来回一次要多久"，两者的边界定义不同。**

## 8. 【统计概念】样本数 n、极差、标准差、CV、SE

> 本节是**概念解释 + 只读分析**：公式是通用统计概念；数字来自对 EXP-004 已有 CSV 的内存复算，
> **项目源码中没有这些计算**（第 4.8 节）。

### 8.1 五个量的定义

设一组间隔样本为 x₁, x₂, …, xₙ，均值为 x̄：

| 量 | 记号 | 定义 | 作用 |
| --- | --- | --- | --- |
| 样本数 | n | 参与统计的样本个数 | 决定结论能有多强；**必须和任何统计量一起报告** |
| 极差 | R | R = max(xᵢ) − min(xᵢ) | 最直观的"总跨度"，但它只看两端，对中间样本不敏感 |
| 标准差 | s | s = √( Σ(xᵢ − x̄)² / (n − 1) )（**样本标准差**，n−1 分母） | 描述"样本平均偏离均值多远" |
| 变异系数 | CV | CV = s / x̄（常写成百分数） | 把离散程度除以均值，便于跨量级比较 |
| 标准误 | SE | SE = s / √n | 描述"均值本身有多不确定"；样本越多，SE 越小 |

三点口径说明（本课统一）：

1. **本课所有标准差与 CV 一律使用样本标准差（n − 1 分母）**。如果使用总体标准差（n 分母），数值会略小（例如半周期的总体标准差为 0.858032 s、总体 CV 为 25.24%）——引用时要说清楚用的是哪一种；
2. 当 n = 2 时，样本标准差退化为 s = |x₁ − x₂| / √2，只有一个"差"在支撑结论，极其脆弱；
3. CV 是无量纲的，但**它不能替代样本数**：n = 2 时再小的 CV 也不能证明"长期稳定"。

同一批数据里，**valley→valley 的 CV 只有 1.71%，但它只有 2 个样本**：

## 9. 【周期可信度】判断框架

> 本节是**概念解释**：四步框架是本课建立的教学判据思想，
> **当前项目源码中没有任何这样的检查代码**（第 4.8 节）。

### 9.1 四步框架

判断"这个周期值可不可信"，依次检查四件事：

| 步骤 | 检查内容 | 要回答的问题 |
| --- | --- | --- |
| ① 样本量 | 我们手里有多少个间隔样本？ | n 够不够支撑一个结论？ |
| ② 三法互证 | peak→peak、valley→valley、半周期法（2 × 半周期均值）三种结果是否互相印证？ | 不同定义算出来的周期是否一致？ |
| ③ 相对离散程度 | CV / 极差相对均值有多大？ | 单个样本之间的差异是否已经大到"不能用同一个周期描述"？ |
| ④ 采样粒度解释 | 这些离散能不能由视频的采样粒度（1 帧的时长）解释？ | 波动是真实运动差异，还是只是"落在不同帧格"上的测量效应？ |

四步缺一不可。四步都通过，才有资格"谨慎报告"一个周期值；任何一步不通过，都只能停留在"存在往复结构"的描述上。

### 9.2 核心结论："算出一个平均周期" ≠ "运动真的具有稳定周期"

> **"算出一个平均周期"和"运动真的具有稳定周期"是两件事情。**

任何一串数都可以算出均值——哪怕它们彼此毫不相似；
平均周期的存在只说明"arithmetic 上有一个中心值"，不说明这个运动在物理上真的以这个周期重复。

因此工程上的顺序必须是：

```text
先看数据是否支持"周期"这个概念
→ 再决定要不要报告周期值
→ 周期被证明可信之后，才报告频率
```

### 9.3 EXP-004 逐条对照（只读分析）

| 步骤 | 检查内容 | EXP-004 的实际情况 | 是否通过 |
| --- | --- | --- | --- |
| ① 样本量 | n | 半周期 n=5；peak→peak n=2；valley→valley n=2 | **否**（整周期线路只有 2 个样本） |
| ② 三法互证 | 三种方法的均值 | 6.345120 / 7.575890 / 6.799174 s，相对跨度 18.10% | **否**（不互相印证） |
| ③ 相对离散程度 | CV / 极差 | 半周期 CV = 28.22%，极差 2.461540 s（约 2.33 倍） | **否**（离散过大） |
| ④ 采样粒度解释 | 与 1 帧比较 | 半周期帧差 111 ～ 259 帧、跨度 148 帧（第 11 节） | **否**（远超 1 帧） |

### 9.4 本课对 EXP-004 的结论（必须原样记住）

> **EXP-004 可以确认有明显往复运动；但不应据此报告一个正式、稳定的单一周期值。**

## 11. 【采样粒度】为什么"离散小"也要和帧比一比

> 本节把**真实数据**与**概念解释**放在一起：数字全部来自封板清单与 `results\` CSV 的只读复算；
> "1 帧能解释多少波动"是概念解释。

### 11.1 M6：约 16 / 16.5 / 17 帧一个峰—峰间隔（真实数据）

- 从第 82–93 行的 10 个峰可以算出 9 段峰—峰帧差：16 / 17 / 16 / 16 / 16.5 / 16.5 / 16 / 16 / 16.5 帧；
- 即"约 16 / 16.5 / 17 帧一个峰—峰间隔"，帧差均值 = 146.5 / 9 = 16.2778 帧；
- M6 视频为 **30 fps**：**1 帧 ≈ 1 / 30 ≈ 0.0333 s**；
- 16.2778 帧 ÷ 30 fps = **0.542593 s**——这正是 `T_exp` 的来源；
- 9 段间隔的极差 = 0.0333 s，**恰好是 1 帧**；三个统计线路的样本标准差都在 0.28 ～ 0.44 帧之间（小于半帧）。

**结论**：M6 的小波动（约 ±1 帧）**接近采样格点本身**，因此"离散主要来自 30 fps 的采样粒度"是一个合理、可检验的解释。

> 注意一个容易混淆的地方：报告第 169 行"互差 ≤ 0.09%"说的是**三种方法的均值之间**的差异，
> 而 CV（2.23% / 2.71% / 3.45%）说的是**单个间隔样本之间**的离散。两者不矛盾，但检查的对象不同——
> ②看"均值是否互相印证"，③看"单个样本是否离散"，这也是四步框架里把它们分成两步的原因。

### 11.2 EXP-004：半周期帧差 111 / 236 / 225 / 191 / 259（真实数据）

- 五个半周期候选的帧差为 **111 / 236 / 225 / 191 / 259 帧**；
- 最大 259 帧 − 最小 111 帧 = **跨度 148 帧**；
- EXP-004 的 track CSV 时间步长约 **0.016632 s**（≈ 60.12 fps，由 `time_s` 列差读出）；
- 148 帧 × 0.016632 s ≈ 2.4615 s，与半周期候选极差 2.461540 s 一致；
- 半周期候选的样本标准差 0.959309 s ≈ **57.7 帧**。

**结论**：EXP-004 的离散是"上百帧"量级的差异。**显然不能解释成单纯的 1 帧采样误差**。

### 11.3 两条数据链的采样粒度对照

| | M6 外部公开视频 | EXP-004 动态实验 |
| --- | --- | --- |
| 帧率 | 30 fps | ≈ 60.12 fps（`time_s` 列差） |
| 1 帧时长 | ≈ 0.0333 s | ≈ 0.016632 s |
| 周期候选的单位间隔 | 约 16 ～ 17 帧 | 半周期 111 ～ 259 帧 |
| 单样本离散（帧） | 0.28 ～ 0.44 帧（< 1 帧） | 半周期样本标准差 ≈ 57.7 帧 |
| 采样粒度能否解释离散 | **能**（波动落在 1 帧格点附近） | **不能**（跨度 148 帧） |

**一句话**：判断周期可信度时，**不能只看百分数的大小**——必须把离散换算成"多少帧"，再和采样粒度比较。

## 12. 【频率】f = 1 / T 的前置条件

> 本节是**概念解释**；M6 的数值是**真实数据（冻结记录）**；EXP-004 没有可报告的频率。

### 12.1 定义与单位

```text
f = 1 / T

T：周期，单位 s（秒）——完成一次完整来回所需的时间
f：频率，单位 Hz（赫兹）——每秒完成多少次完整来回
```

例：T = 0.542593 s → f = 1 / 0.542593 ≈ 1.843003 Hz。

频率与周期互为倒数，所以**周期不可信时，频率同样不可信**——这一步没有"额外的魔法"。

### 12.2 M6 的 T → f（真实数据，冻结记录）

- `src\m63_final_visualization.py` 第 113 行：`T_exp = 0.542593`（单位 s）；
- 第 114 行：`f_exp = 1.843003`（单位 Hz）；
- `docs\M6.3_FINAL_REPORT.md` 第 159 行：f_exp = 1.843003 Hz（= 1 / T_exp）；
- 只读复算：1 / 0.542593 ≈ 1.843002 Hz，与冻结值一致到显示精度。

**必须说明**：这个结果来自 **M6 外部公开视频的冻结数据**，**不是 M5 运行时周期计算代码生成的**。

### 12.3 什么时候才可以报告频率

顺序固定为：

```text
① 数据支持"存在重复运动"
→ ② 间隔统计与三法互证
→ ③ 相对离散与采样粒度检查
→ ④ 周期可信
→ ⑤ 才报告频率 f = 1 / T
```

对 EXP-004：第 9.3 节的四步没有全部通过，所以**不报告正式周期值，也不报告由此推出的频率**。

## 13. 【教学示例】三组玩具间隔（非项目数据）

> 以下数字是为了讲解而临时构造的，**不是项目数据**，与 EXP-004、M6 都无关。
> 三组都以"帧"为单位（假设 30 fps，1 帧 = 0.0333 s），这样可以同时练习"均值 / 离散 / 采样粒度 / 样本数"四个概念。

**示例 A：离散落在 1 帧格点内，均值有资格继续讨论**

```text
周期候选（帧）：16, 16, 16, 17, 16, 17, 16, 16
n = 8
均值 = 16.25 帧 ≈ 0.541667 s
极差 = 1 帧（0.0333 s）
样本标准差 ≈ 0.463 帧
CV ≈ 2.85%
```

- 离散几乎等于采样格点本身（1 帧），④"采样粒度检查"通过；
- n = 8，样本也不是太少；
- 这组数据才有资格继续讨论"周期值是多少"。

**示例 B：均值接近，但离散远超采样格点**

```text
周期候选（帧）：12, 14, 15, 16, 17, 18, 20, 21
n = 8
均值 = 16.625 帧 ≈ 0.554167 s
极差 = 9 帧（0.3 s）
样本标准差 ≈ 3.02 帧
CV ≈ 18.17%
```

- 均值与示例 A 相近（都在 0.55 s 附近），但极差 9 帧 ≈ 9 个采样格点；
- ④"采样粒度检查"不通过：离散无法用"落在不同帧格"解释；
- 这组数据只能说"发生了往复运动"，不能宣布一个稳定周期。

**示例 C：n = 2，再小的 CV 也不能外推**

```text
周期候选（帧）：16, 17
n = 2
均值 = 16.5 帧 = 0.55 s
极差 = 1 帧
样本标准差 ≈ 0.707 帧 = 0.023570 s
CV ≈ 4.29%
```

- 两个样本确实只差 1 帧，CV 也不大；
- 但 n = 2，样本标准差只是 |17 − 16| / √2 的变形——**没有任何中间样本能说明第三次、第四次会怎样**；
- 这组数据只能描述"这两个样本有多接近"，不能外推为"长期稳定"。

三个示例合起来说明：**同样的"平均周期"，可信度可以完全不同；判断必须同时看样本量、离散程度与采样粒度。**

## 14. 【工程思想】先验证数据是否支持周期，再报告周期；周期可信后再报告频率

> **本课工程思想**：
>
> **"先验证数据是否支持周期，再报告周期；周期可信后再报告频率。"**

展开成操作顺序：

1. **素材**：用 turns 的 `time_s` + `kind` 得到事件序列（第 4 节）；
2. **间隔**：按第 5 节的概念流程算出半周期候选与完整周期候选；
3. **统计**：至少报出 n、均值、极差、标准差、CV、SE（第 8 节）；
4. **可信度**：过第 9 节四步框架（样本量 / 三法互证 / 相对离散 / 采样粒度）；
5. **周期**：四步全部通过，才给出"候选周期值"；
6. **频率**：周期被证明可信之后，才由 f = 1 / T 得到频率。

三条纪律：

- **不要因为能够算出一个平均值，就默认它是物理上可信的周期**；
- 报告任何统计量时必须同时报告样本量 n；
- 不同的数据链（M5 / M6）各自独立，结论不能互相搬运（第 10.6 节）。

## 16. 本课核心概念（18 条）

1. **项目真正实现的是什么**：turns、segments，以及 `frame` / `time_s` / `x_px` / `ds_mm` / `kind` / `direction` / `travel_px` 这些字段（第 4.1 节）；
2. **项目没有运行时实现的四件事**：interval statistics、formal period calculation、runtime frequency calculation、period consistency criterion（第 4.8 节）；
3. **第 28 行是工程边界原文**："不做平滑 / 滤波 / 插值 / 补帧 / 补零 / 预测 / FFT / 频率 / 周期 / 振幅分析。"；
4. **`detect_turning_points()`（第 491–622 行）只产出 turns / segments**；`describe()`（第 569–576 行）提供 `frame` / `time_s` / `x_px` / `ds_mm`；turns 组装（第 581–592 行）加 `kind` 与方向；segments 组装（第 594–620 行）加 `direction` / `travel_px`；
5. **打印边界**：第 763、794–799、806–821、827–842 行只有转向点数量、运动段数量、每个转向点、每个运动段——**没有任何时间间隔 / 周期 / 频率计算**；
6. **从 turns 到时间间隔的五步流程**（概念伪代码）：按 kind 分组 → 相邻 peak 相减 → 相邻 valley 相减 → 相邻 peak/valley 交替事件相减 → 得到完整周期候选与半周期候选；
7. **半周期候选**：peak→valley、valley→peak；**完整周期候选**：peak→peak、valley→valley；
8. **一个运动段 ≠ 一个周期**：首尾段可能被视频边界截断（第 507–508 行）；一段只代表一个方向；周期应由同类事件之间定义；
9. **EXP-004 的真实数据**：6 个转向点时间；5 个半周期候选 1.846156 / 3.925159 / 3.742207 / 3.176718 / 4.307696 s（帧差 111 / 236 / 225 / 191 / 259）；peak→peak 5.771315 / 6.918925 s（均值 6.345120 s，n=2）；valley→valley 7.667366 / 7.484414 s（均值 7.575890 s，n=2）；2 × 半周期均值 6.799174 s；三者相对跨度 18.10%；
10. **五个统计概念**：n / 极差 / 标准差（样本标准差，n−1）/ CV = s / x̄ / SE = s / √n；
11. **EXP-004 的统计量**：半周期 CV = 28.22%（n=5）；peak→peak CV = 12.79%（n=2）；valley→valley CV = 1.71%（n=2，不能据此判断长期稳定）；
12. **统计指标不能脱离样本量单独解释**：报告 CV / 均值 / 标准差时必须同时报告 n；
13. **周期可信度四步框架**：① 样本量；② peak→peak、valley→valley、半周期法是否互相印证；③ 相对离散程度；④ 离散是否能够由视频采样粒度解释；
14. **核心结论**："算出一个平均周期"和"运动真的具有稳定周期"是两件事情；
15. **EXP-004 的可信度结论**：可以确认有明显往复运动；但不应据此报告一个正式、稳定的单一周期值；
16. **M6 对照**：`src\m63_final_visualization.py` 第 82–105 行是 10 峰 + 10 谷封板极值；第 112–127 行 `FROZEN` 里第 113 行 `T_exp = 0.542593`、第 114 行 `f_exp = 1.843003`；`docs\M6.3_FINAL_REPORT.md` 第 154–169 行记录三种方法；只读复算 peak→peak ≈ 0.542600 s、valley→valley ≈ 0.542589 s、2 × 半周期均值 = 0.542105 s、相对跨度 ≈ 0.0913%；
17. **采样粒度**：M6 约 16 / 16.5 / 17 帧一个峰—峰间隔，30 fps 下 1 帧 ≈ 0.0333 s，小离散接近采样格点；EXP-004 半周期帧差 111 / 236 / 225 / 191 / 259、跨度 148 帧，显然不能解释成 1 帧采样误差；
18. **频率**：f = 1 / T（T 单位 s、f 单位 Hz）；M6 的 f ≈ 1.843003 Hz 来自外部公开视频的冻结数据，不是 M5 运行时周期计算代码生成的；工程思想是"先验证数据是否支持周期，再报告周期；周期可信后再报告频率"。

## 17. 易错点（与 `COURSE_MISTAKES.md` 的 L14 条目对应）

1. **把"能算出平均周期"当成"运动有稳定周期"。** 均值只是算术中心；必须过四步可信度检查；
2. **报告 CV / 标准差 / 均值时不报样本量 n。** valley→valley 的 CV 只有 1.71%，但 n=2；统计指标不能脱离样本量单独解释；
3. **只看百分数大小，不看采样粒度。** M6 的离散约 1 帧（0.0333 s）；EXP-004 的半周期跨度 148 帧——同样的"百分数思维"会得出完全相反的判断；
4. **把"三法互差 ≤ 0.09%"与"单个样本的 CV"混为一谈。** 前者是均值之间的一致性，后者是单样本离散；检查对象不同；
5. **用最短或最顺眼的间隔宣布周期。** 例如只看 3.7 s 左右的间隔，忽略 1.846156 s 与 4.307696 s 相差约 2.33 倍；
6. **把只读分析算出的间隔与统计量写成"项目已经实现的功能"。** 项目源码只有 turns / segments；间隔统计是 L14 的只读分析；
7. **把 M6 的 T = 0.542593 s / f = 1.843003 Hz 当成 EXP-004 的结论。** 那是 M6 外部公开视频（EXP-EXT-LAB67-V1）的冻结记录；
8. **以为打印部分会输出间隔 / 周期 / 频率。** 第 763、794–799、806–821、827–842 行只打印数量、转向点与运动段信息；
9. **在周期不可信时仍然报告频率。** f = 1 / T；周期不可信，频率同样不可信；
10. **把段 1（f0 → f491）或段 7（f1513 → f1765）当作完整半周期样本。** 它们的一端是视频边界，不是转向点（第 507–508 行）；
11. **为了"看起来更整齐"而平滑、插值、改阈值。** 第 28 行明确禁止；本课也不修改任何数据；
12. **提前展开 FFT / 频谱 / 简谐振动。** 本课只登记名称，不讲授、不计算。
