## 5. 【概念解释】时域与频域：两个问题，两种视角

- **时域（time domain）回答**：信号**随时间**怎么变化。例：y0(t) 在 2.53 s 到 7.83 s 之间上下往复，在哪些时刻到峰、哪些时刻到谷。
- **频域（frequency domain）回答**：信号**主要包含哪些频率成分**。例：这段往复运动的"主频率"大约是多少 Hz。
- 同一个信号可以同时用两种视角看：时域看"波形在时间轴上的形状"，频域看"波形里各个频率成分的强弱"。两种视角不改变物理对象本身。

**M6 的两条路线（本课对照表）**：

| 路线 | 输入 | 中间量 | 输出 | 本项目状态 |
| --- | --- | --- | --- | --- |
| 时域（L17 路线） | y0(t)（160 点） | 10 峰 + 10 谷 → 峰—峰 / 谷—谷 / 半周期 | 周期 T、频率 f | 冻结值 T_exp = 0.542593 s、f_exp = 1.843003 Hz（第 113–114 行） |
| 频域（L18 学概念） | y0(t)（同一 160 点） | FFT 主峰、FFT 分辨率 | 主频 f_FFT | 冻结值 f_FFT = 1.875 Hz、df_fft = 0.1875 Hz（第 119–120 行） |

> 注意：表中"频域"一行在本项目里的意思是"**曾经用 FFT 做过交叉验证，并把结果冻结**"，不是"当前代码里有一条运行时的频域计算链"——见第 3 节的检索结论。

## 6. 【概念解释】DFT 与 FFT：算法不是新的物理规律

- **DFT（离散傅里叶变换）**：把一段**有限长度的离散时间信号**（例如 y0(t) 的 160 个采样点）表示为**频率成分**的表示方式。写成概念公式（一般理论，不是项目源码）：

  X(k) = Σₙ₌₀^{N−1} x(n) · e^(−j·2π·k·n/N)，k = 0, 1, …, N−1

  其中 x(n) 是第 n 个采样点，X(k) 是第 k 个频率成分（复数，含幅值与相位）。

- **FFT（快速傅里叶变换）**：**快速计算 DFT 的一类算法**。同一个 DFT 结果可以用朴素定义直接算，也可以用 FFT 更快地算出来——两者的数学结果一致，区别是计算速度（复杂度）。
- **必须强调**：FFT **不是新的物理规律，也不是新的测量量**。它没有测到新数据，只是把同一条 y0(t) 序列"换一种表示方式"来展示其频率结构。

**三层区分（本课要能一口气说清）**：

1. 物理对象：弹簧上小球/暗带的**真实振动**；
2. 测量量：从视频里逐帧提取的 **y0(t) 位置序列**（160 个采样点，30 fps）；
3. 表示 / 算法：DFT / FFT——对第 2 层数据做的数学变换，用来回答"主要频率成分是什么"。

DFT / FFT 的前提是"有限长度离散序列"；M6 的 y0(t) 恰好就是这样一段序列（`results\EXP-EXT-LAB67-V1_trajectory.csv`，160 行数据），这也是它能做 FFT 交叉验证的原因。

## 7. 【概念解释 + 本课核对计算】频率分辨率：df ≈ fs / N ≈ 1 / T_record

**一般概念（本课理论，不是项目源码）**：

- **df ≈ fs / N**：频率分辨率约等于"采样率 ÷ 采样点数"；
- 也可理解为 **df ≈ 1 / T_record**：分辨率约等于"总记录时长的倒数"；
- 两者等价的前提是采用同一口径 T_record = N / fs（N 个采样点、采样间隔 1/fs）；
- 物理含义：df 是频谱上相邻频率格点的间隔，它限制了"两条靠得很近的频率成分能不能被分开"（格点与频谱泄漏的细节留到下一课）。

**M6 的核对计算（本课内存中完成，未写任何文件）**：

| 量 | 计算 | 结果 | 依据（只读核对） |
| --- | --- | --- | --- |
| 采样率 fs | — | **30 Hz** | `README.md` 第 46 行"30 fps"；`src\m63_final_visualization.py` 第 75 行页脚"30 fps" |
| 采样点数 N | — | **160** | `results\EXP-EXT-LAB67-V1_trajectory.csv` 160 行数据；`README.md` 第 47 行"160 帧" |
| 频率分辨率 df | 30 / 160 | **0.1875 Hz** | 与第 120 行 `df_fft = 0.1875` 一致；报告第 180 行 |
| 记录长度 T_record | 160 / 30 | **5.3333 s** | 报告第 181 行"记录长度 5.3333 s"；`README.md` 第 47 行"5.3333 s" |
| 奈奎斯特频率 | 30 / 2 | **15 Hz** | 一般概念 fs/2；f_exp ≈ 1.84 Hz、f_FFT = 1.875 Hz 都远低于 15 Hz |

**口径说明（重要，避免以后的记录犯错）**：这里的"记录长度 5.3333 s"采用的是 **N / fs 口径**（160 / 30）；若改用"首末采样点时间戳之差"口径，则为 159 / 30 = **5.3000 s**（真实数据 time_s 首行 2.533333 s、末行 7.833333 s，差值正好 5.3000 s）。两个口径相差 1 帧（约 0.0333 s），引用时必须说清用的是哪一个；本课跟随报告与 README 采用 5.3333 s（N/fs 口径）。

**必须区分**：以上全部是**本课的一般理论 / 核对计算**，**不是当前 VisionMotion 源码实现**——源码里没有任何 FFT 计算（第 3 节已逐模式检索确认），`df_fft = 0.1875` 是 M6.3 封板时冻结下来的结果（第 120 行）。

## 10. 【概念解释】FFT 为什么不能替代时域

| 视角 | 能回答 | 不能直接回答 |
| --- | --- | --- |
| 时域（y0(t)、峰谷、转向点） | 找具体峰 / 谷；找转向点；定位事件时间；计算峰峰周期 | 信号整体由哪些频率成分构成（需要另一种表示） |
| 频域（FFT 主峰、频谱） | 找主要频率；看整体频率成分 | 某个峰发生在哪一帧；某次异常发生在哪个时刻 |

**关键理解**：FFT 把"时间定位"信息压缩掉了——频谱只告诉你"有哪些频率成分、强度多少"，不保留"这件事发生在第几秒"。所以：

- 需要"哪一帧到峰、哪一帧异常" → 用时域；
- 需要"整体主频是多少、有没有其他频率成分" → 用频域；
- 两者是互补视角，不是互相替代。

**报告第 185 行原文（必须背下）**：

> FFT 仅作为独立的频域交叉验证，不替代时域峰—峰周期测量；本报告的中心频率取自时域结果。

同一句话在 `src\m73_presentation.py` 第 424 行以 PPT 文案形式出现："FFT 仅作独立交叉验证，不替代时域峰间周期测量。"

## 13. 【教学示例】玩具序列：8 个采样点看"格点"（非项目数据）

以下数字只为帮助理解 df ≈ fs / N，**不是 VisionMotion 的真实数据**。

**场景**：假设一段信号用 fs = 8 Hz 采样、共采 N = 8 个点（记录时长 8/8 = 1 s）。按一般公式：

- df ≈ fs / N = 8 / 8 = **1 Hz**；等价地 df ≈ 1 / T_record = 1 / 1 = 1 Hz；
- 奈奎斯特频率 = fs / 2 = **4 Hz**；
- 频率格点间隔就是 1 Hz。

**示例 A（频率恰好在格点上）**：信号成分是 1 Hz。1 Hz 正好是格点，频谱在 1 Hz 处出现明确主峰——这正是"信号主频 = 频谱主峰"的直观版本。

**示例 B（频率不在格点上）**：把成分换成 1.5 Hz。1.5 Hz 不在 1 Hz 间距的格点上，频谱能量会分散到相邻格点（1 Hz 与 2 Hz 都会出现非零幅值）——这就是"频谱泄漏"的直观预告，它的数学细节与处理方法留到下一课。

**和本课的关系**：M6 核对计算中 df = 30/160 = 0.1875 Hz、奈奎斯特 15 Hz，与上面玩具例子的公式完全一致，只是数字换成了项目参数；但请注意——**项目里的 df_fft = 0.1875 是冻结值，不是当前代码算出来的**（第 120 行；第 7 行）。

## 16. 一句话总结

> L18 记录了"从时域到频域——FFT 为什么能找到振动主频"：当前 `src\` 与 `demo\` 全部 Python 文件检索不到 `np.fft` / `numpy.fft` / `rfft` / 作为计算的 `fft(`（唯一 "fft(" 命中是 `src\m73_presentation.py` 第 403、647 行的函数名 `slide_06_period_fft`），也没有运行时生成的频率轴数组与频谱幅值数组，`src\m63_final_visualization.py` 第 7 行明确"不重新计算周期 / 频率 / 极值 / FFT"——**当前代码没有实时运行 FFT**。FFT 主峰频率 f_FFT = 1.875、频率分辨率 df_fft = 0.1875 是第 119–120 行的**冻结结果**（第 112–127 行 `FROZEN`；报告第 179–180 行），不是当前代码实时计算出来的。概念上：时域回答"信号随时间怎么变化"（M6：y0(t)、峰谷、T_exp = 0.542593 s、f_exp = 1.843003 Hz），频域回答"信号主要包含哪些频率成分"（M6：FFT 主峰 f_FFT = 1.875 Hz）；DFT 把有限长度离散时间信号表示成频率成分，FFT 是快速计算 DFT 的一类算法——**FFT 不是新的物理规律，也不是新的测量量**。频率分辨率的一般概念是 df ≈ fs / N，也可理解为 df ≈ 1 / T_record；M6 核对计算：fs = 30 Hz、N = 160 → df = 30/160 = 0.1875 Hz、记录长度 160/30 = 5.3333 s（N/fs 口径；首末时间戳差为 5.3000 s）、奈奎斯特频率 15 Hz——这些是**本课的一般理论 / 核对计算，不是当前源码实现**。时域与 FFT 的对照：差值 1.875 − 1.843003 = 0.031997 Hz，相对差 ≈ 1.74%，半格 0.09375 Hz，**差值 < 半格** → 两者属于同一数据上的不同方法，结果在分辨率范围内一致，**不能说 FFT 的 1.875 Hz 更正确**（报告第 185–187 行）。图 B（`make_figure_b()` 第 388 行定义、绘图主体至第 478 行、第 479–485 行返回）**不是 FFT 频谱图**，只是三个频率数值（实验 / 理论 / FFT）的对照图：第 398–399 行读取冻结 f_FFT、df_fft，第 428–430 行画 FFT 分辨率段 ±df/2，第 431–433 行画 FFT 主峰标记，第 438–443 行是类别纵轴，第 445 行是频率横轴。FFT 不能替代时域：时域能找具体峰 / 谷、转向点、事件时间与峰峰周期；FFT 只能找主要频率和整体频率成分，无法直接告诉某个峰发生在哪一帧——二者互补；`docs\M6.3_FINAL_REPORT.md` 第 185 行明确"FFT 仅作为独立的频域交叉验证，不替代时域峰—峰周期测量"。`src\m73_presentation.py` 第 421–424 行虽然有"仅对原始 y₀(t) 做 rFFT（仅减均值）"（第 423 行）等文字，但那只是 PPT 文案（字符串来自第 75–82 行 `FROZEN`），当前可执行代码里没有 FFT 实现。课程衔接：**L16 视频 → y0(t)；L17 y0(t) → 峰谷 → T → f；L18 y0(t) → FFT → 频域主峰 → f_FFT；两条路线互相验证；下一课：采样、频率格点、频谱泄漏，以及为什么冻结 FFT 结果不能等同于"当前代码支持 FFT"。**
