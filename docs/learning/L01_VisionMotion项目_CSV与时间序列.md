## 2. VisionMotion 到底在做什么

VisionMotion 是一个基于计算机视觉的低成本、非接触式位移与振动监测项目。

它的基本想法是：不用触碰目标，只用普通摄像设备（手机 / 电脑摄像头）拍摄目标运动的视频，然后从视频中提取出目标的位置随时间变化的数据。本项目不使用深度学习或复杂的跟踪算法，重点在于：整条测量链路能够跑通、每一步都能解释清楚、结果可以复现。

本节课建立的核心认识是这样一条链路：

```text
视频
→ 一帧一帧处理
→ 每一帧找到目标
→ 得到目标的位置
→ 按时间记录位置
→ 形成时间序列
```

本节课的重点，就是理解其中最关键的转化：

**视频 → 目标位置 → 时间序列**

也就是说：把"一段运动的视频"，变成"一串随时间排列的位置数字"。

> 说明：项目后续还会在这条时间序列上继续做周期、频率、FFT、物理模型等分析，这些属于后面的课程内容。本节课只要真正理解到"时间序列"这一步即可，不要求掌握后续分析，也不要把它们写成本节课已经掌握的知识。

本节课使用的数据来自项目里的外部公开教育视频（30 fps）。当前正式分析区间为 frame 76–235，共 160 个数据时刻。

## 3. 视频、Frame 与 FPS

### 3.1 视频就是连续排列的图片

计算机并不直接"理解"一段连续的运动。在计算机眼中，视频可以理解为连续排列的一张张图片：

```text
Frame 0
Frame 1
Frame 2
Frame 3
……
```

这些图片按时间顺序排列、快速播放，人眼看起来就是连续的运动。其中每一张图片称为**一帧（Frame）**，每一个 Frame 都代表一个具体的时间瞬间。

一句话记忆：

> 视频不是计算机直接理解的一条连续运动，而是一张张连续画面组成的数据。

### 3.2 FPS：每秒多少帧

FPS = Frames Per Second，即"每秒帧数"。

本项目当前使用的外部视频是 **30 fps**，含义是：每秒 30 帧，也就是每秒钟有 30 张图片。

相邻两帧的时间间隔：

```text
Δt = 1 / 30 s ≈ 0.033333 s
```

### 3.3 FPS 为什么直接决定时间分辨率

因为计算机只能"一帧一帧地看得见"：

- 帧与帧之间发生的事情，计算机看不到；
- 它最多只能每隔 1/30 s ≈ 0.033333 s 取一个"位置样本"。

所以 FPS 直接决定**时间分辨率**：30 fps 意味着时间分辨率约为 0.033333 s。如果目标的某种变化发生在 1/30 s 以内，这段视频就无法把它分辨出来。后续如果关心极值出现的准确时刻，它的时间定位精度也受这一帧间隔的限制。

## 4. frame 与 time_s

在 trajectory.csv 里，前两列就是 frame 和 time_s。它们都和时间有关，但不是一回事：

- **frame = 视频中的第几帧**，是帧的编号（本视频从 Frame 0 开始编号）；
- **time_s = 这一帧距离视频开始经过了多少秒**，是真实的时间。

当前视频是 30 fps，所以两者满足：

```text
time_s ≈ frame / 30
```

真实数据示例（来自当前 trajectory.csv）：

| frame | time_s | 说明 |
| --- | --- | --- |
| 76 | 2.533333 s | 76 / 30 = 2.53333…，这是本节正式数据的第一个时刻 |
| 77 | 2.566667 s | 77 / 30 = 2.56666… |
| 78 | 2.600000 s | 78 / 30 = 2.60000… |

注意：frame 是"编号"，time_s 是"时间"，两者不能混用。例如 76 / 30 ≈ 2.533 s，而不是 2.5 s。

补充事实：当前正式分析区间为 **frame 76–235**，共 **160 个数据时刻**（每个时刻对应 trajectory.csv 中的一行）。

## 5. trajectory.csv 是什么

### 5.1 CSV 是什么

CSV = Comma-Separated Values（逗号分隔值）。它是一种非常简单的纯文本表格：

- 一行就是一条记录；
- 记录内部用逗号（,）把各个字段分开；
- 第一行通常是"表头"，用来说明每一列是什么。

它用记事本能打开，用 Excel 也能打开，所以在实验记录和数据分析中很常用。

### 5.2 本项目的 trajectory.csv

当前正式轨迹文件：

```text
results\EXP-EXT-LAB67-V1_trajectory.csv
```

它共有：

- **160 行数据**（对应 160 个数据时刻）；
- **8 列**。

表头为：

```text
frame,time_s,detected,x_px,y0_px,bbox_w_px,bbox_h_px,area_px
```

这个文件里，每一行记录的是：某一个时刻，视觉检测程序从对应那一帧中"量"出来的目标位置和质量信息。它是把"视觉检测结果"变成"可以保存、可以继续计算的数据"的关键文件。

### 5.3 它在项目数据链中的位置

```text
视频 → 逐帧检测 → 每帧的目标位置 → trajectory.csv → 时间序列
```

trajectory.csv 处在承上启下的位置：左边是视觉检测（视频 → 数字），右边是后续分析（数字 → 结论）。本节课只走到"时间序列"为止，不往后走。

特别强调：在这 8 列里，**y0_px 是本阶段最核心的运动信号**。

## 6. CSV 八列详解

| 列名 | 含义 | 单位 | 在项目中的作用 |
| --- | --- | --- | --- |
| frame | 该行数据来自视频中的第几帧（帧编号） | 帧（编号，无单位） | 标记这次测量对应哪一帧；与 time_s 一起构成时间轴 |
| time_s | 该帧距离视频开始经过的时间（time_s ≈ frame / 30） | 秒（s） | 把帧编号换算成真实时间，是时间序列的"时间"一列 |
| detected | 这一帧是否成功检测到合格的目标（True / False） | 无（真 / 假值） | 判断该时刻的测量是否有效；当前正式数据全部为 True |
| x_px | 目标在画面中水平方向的像素位置（暗带外接框中心） | 像素（px） | 仅作为检测质量检查（QC）记录，不是本阶段的正式位置特征 |
| y0_px | 目标竖直方向的像素位置：**暗带上缘的竖直像素位置** | 像素（px） | **本阶段的核心运动信号**；y0(t) 就是用它的数值构成的 |
| bbox_w_px | 检测到的暗带外接框宽度 | 像素（px） | 检测质量指标：看检测区域的宽度是否合理 |
| bbox_h_px | 检测到的暗带外接框高度 | 像素（px） | 检测质量指标：看检测区域的高度是否合理 |
| area_px | 检测到的暗带包含的暗像素个数（面积大小） | 像素个数（可理解为像素面积） | 检测质量指标：看目标区域是否足够大、是否像一条暗带 |

### 6.1 运动信号与检测质量指标要分开

八列可以分成两类：

- **运动信号（1 个）：y0_px** —— 它随时间的变化，就是我们要研究的运动本身；
- **检测质量指标（其余）**：detected、x_px、bbox_w_px、bbox_h_px、area_px —— 它们主要回答三个问题：
  1. 有没有成功检测到？（detected）
  2. 检测区域有多大？（bbox_w_px、bbox_h_px、area_px）
  3. 检测区域的形状是否合理？（bbox_w_px、bbox_h_px）

其中 x_px 虽然也是一个位置，但它在项目里只作为质量检查记录，不是正式位置特征。把检测质量指标当作运动测量量来用，是初学者最容易犯的错误之一。

## 7. 一行 CSV 到底代表什么

这是本节课最重要的认知之一：

> **一行 CSV = 一个时刻的一次视觉测量结果。**

以真实数据中的一行为例：

```text
77,2.566667,True,725.00,508.00,57,5,280
```

逐项解释：

- frame = 77 → 这是视频的第 77 帧；
- time_s = 2.566667 s → 这一帧出现在视频开始后约 2.57 秒处；
- detected = True → 这一帧成功检测到了合格的目标（暗带）；
- x_px = 725.00 px → 检测到的暗带外接框中心的水平像素位置（仅质量检查用）；
- y0_px = 508.00 px → 暗带上缘的竖直像素位置，这是本阶段的正式位置特征；
- bbox_w_px = 57 px → 暗带外接框宽度为 57 像素；
- bbox_h_px = 5 px → 暗带外接框高度为 5 像素；
- area_px = 280 → 这条暗带共有 280 个暗像素。

需要注意：**不要把它简单称为"目标中心坐标"**。本项目的 y0_px 是"暗带上缘的竖直像素位置"——记录的是暗带的上边缘在哪里，而不是整块目标的中心在哪里，更不是整行代表一个"中心点 (x, y)"。

那么 160 行数据是什么意思？就是：160 个时刻，各自做了一次这样的视觉测量，然后按时间顺序排列好。

## 8. 图像坐标系与 y0_px

### 8.1 图像坐标的 y 轴方向和数学课不一样

图像（像素）坐标系的常见约定是：

- 原点在图像的**左上角**；
- x 向右增加；
- **y 向下增加**。

所以：

- y 越小 → 目标在画面中越靠上；
- y 越大 → 目标在画面中越靠下。

这和数学课本里常见的笛卡尔坐标系（y 向上增加）直觉相反，非常容易记反。

### 8.2 本项目中的 y0_px

本项目记录的位置特征 y0_px 是"暗带上缘的竖直像素位置"，它直接使用图像坐标系，因此：

- **y0_px 局部极大 → 画面中的较低位置**；
- **y0_px 局部极小 → 画面中的较高位置**。

真实数据示例：

- frame 77 处 y0_px = 508（数值较小）→ 对应画面中较高的位置；
- frame 85 处 y0_px = 622（数值较大）→ 对应画面中较低的位置。

也就是说：y0_px 从 508 变到 622，表示暗带上缘在画面中**向下**移动了；反过来，y0_px 变小表示它**向上**移动。这也是"y0_px 不是普通坐标、y 轴方向与数学直觉不同"最容易出错的一点。

## 9. 时间序列是什么

**时间序列**的简单定义：按照时间顺序排列的一系列测量值。

在本项目中，trajectory.csv 的两列正好构成一个时间序列：

- 时间轴：time_s → 时间；
- 测量值：y0_px → 测量值。

于是可以把本项目的位置测量写成：

```text
y0_px = y0(t)
```

读作"y0 是时间 t 的函数"。更具体地说：

- 每隔约 1/30 秒，程序记录一次目标（暗带上缘）的位置；
- 这些位置值按时间顺序排列起来，就形成了 y0(t)。

它有两个特点：

1. **离散**：只有 160 个时刻有数值，时刻与时刻之间没有数据（计算机看不到帧与帧之间发生了什么）；
2. **是测量信号**：数值来自对视频每一帧的实际视觉检测，而不是凭空画出来的曲线。

所以 y0(t) 是一个"随时间变化的离散测量信号"。本节课的任务到此为止：把它理解清楚。之后课程里的周期、频率等分析，都是在这条 y0(t) 上继续做的事情。

## 11. 本节课最重要的概念

1. 视频在计算机里是"一帧一帧的图片序列"，Frame 是一个时间瞬间的一幅画面；
2. FPS 是每秒帧数，直接决定时间分辨率；本视频 30 fps，相邻帧间隔 1/30 s ≈ 0.033333 s；
3. frame 是帧编号，time_s 是时间，两者关系为 time_s ≈ frame / 30；
4. CSV 是逗号分隔的纯文本表格；trajectory.csv 有 160 行数据、8 列；
5. 一行 CSV = 一个时刻的一次视觉测量结果；
6. y0_px 是暗带上缘的竖直像素位置，是本阶段的核心运动信号；
7. 图像坐标系 y 轴向下增加：y0_px 越大越靠下，越小越靠上；
8. y0_px = y0(t)：把位置测量按时间排列，就得到时间序列；
9. 时间序列是"按时间顺序排列的一系列测量值"，它是一个离散的测量信号；
10. trajectory.csv 位于"视频 → 目标位置 → 时间序列"这条数据链的中间位置。

## 12. 本节课容易犯的错误

1. **把 frame 和 time_s 当成一回事**
   - frame 是"第几帧"（编号），time_s 是"过了多少秒"（时间）。例如 frame 76 对应 time_s ≈ 2.533333 s，两者数值完全不同。

2. **把视频当成一个连续、可以直接计算的数学函数**
   - 计算机拿到的是离散的帧序列，它只"看见"了 160 个时刻的 160 张画面，帧与帧之间的过程没有数据。y0(t) 是离散测量信号，不是一条连续曲线。

3. **把图像 y 轴当成数学坐标系那样向上增加**
   - 图像 y 轴向下增加：y0_px 局部极大对应画面中较低的位置，y0_px 局部极小对应画面中较高的位置。

4. **把 y0_px 和 x_px 混为一谈**
   - x_px 是水平方向的像素位置（且仅作质量检查），y0_px 是竖直方向的像素位置；本阶段的正式位置特征是 y0_px。

5. **不清楚 y0_px 才是本阶段的运动信号**
   - 其它列也在变化，但真正代表"运动"的是 y0_px（暗带上缘的竖直位置）；分析运动时应使用 y0_px。

6. **把检测质量字段当成运动测量量**
   - detected、bbox_w_px、bbox_h_px、area_px 主要描述"有没有检测到、检测区域有多大、形状是否合理"，它们不是运动本身。

7. **忘记"一行 CSV 就是一个瞬间的一次测量"**
   - 160 行 = 160 个时刻的 160 次测量；不要把它想象成一条已经画好的连续曲线。
