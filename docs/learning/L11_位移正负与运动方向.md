### 4.2 s0 是参考位置，不带方向（概念解释 + 源码依据）

- `s0` 是 L10 定义的时间窗口内 `valid=True` 帧 `s_px` 的平均值（`compute_s0()`：`src\displacement.py` 第 317～354 行）；
- 它和 `s_px` 在**同一条尺、同一个坐标系**上，都是一个"位置读数"；
- 所以 **`s0` 本身不带"正方向"**，它只是"参考位置"这个位置坐标。

`ds` 的正负来自 `s_px` 与 `s0` 的**相对关系**：

| 相对关系 | `ds` 的符号 | 读法（概念解释） |
| --- | --- | --- |
| `s_px > s0` | `ds > 0` | 这一帧在参考位置的**正侧**（沿 `U` 指向的一侧） |
| `s_px < s0` | `ds < 0` | 这一帧在参考位置的**负侧** |
| `s_px = s0` | `ds = 0` | 这一帧恰好落在参考位置上 |

注意："正侧 / 负侧"这两个词在源码里没有出现过（源码只写 `ds_px = s_px - s0`）——它们是**概念解释**，用途是帮助读数据；遇到争议时回到源码第 368 行、回到 `U` / `U_004` 的方向定义。

### 4.3 ds 的大小：离参考位置 s0 有多远（概念解释）

- `|ds_px|` = 这一帧离参考位置沿尺方向差了多远（像素）；
- `|ds_mm|` = 同一件事的毫米版本；
- 它是**沿尺方向的有号投影距离的绝对值**，不是二维欧氏距离（二维欧氏距离要另算，本项目不产出这个量）；
- 大小只回答"多远"，**不回答"多快"**：从 0 到 60 mm 用 1 秒还是 10 秒，`|ds|` 一样，只是快慢不同。

### 4.4 三条"不等于"（本课最重要的概念解释）

1. **`ds` 的正负 ≠ 好坏。** 负号只是"落在参考位置的负侧"，不是错误、不是失败、不是质量差；正号也不代表"好"。三份真实数据里负号帧分别有 34 / 18 / 161 个，它们和正号帧一样是正常测量结果。
2. **`ds` 的大小 ≠ 快慢。** `|ds|` 是"离参考位置多远"，不是速度；快慢要用单位时间的变化量（Δds / Δt）才能描述，本项目没有速度字段。
3. **`ds` 的正负 ≠ 运动方向。** 这是本课最核心的一条：判断"正在往哪边运动"要看 **Δds 的符号**（第 6 节），而不是看 `ds` 的符号。真实例子见第 9 节（负侧向正运动、正侧向负运动）。

## 6. Δds：运动方向由变化量决定

### 6.1 定义（概念解释）

> **Δds = ds[i+1] − ds[i]**（相邻两帧的位移读数之差）

- 用 `ds_px` 算或 `ds_mm` 算都可以：两者同号（第 340 / 350 行的除数为正）；
- Δds 的单位是 px（用 `ds_px` 时）或 mm（用 `ds_mm` 时）；
- Δds 描述的是"**这一段间隔里位置读数往哪边变**"，不是"现在的位置在哪一侧"。

概念伪代码（**不是 VisionMotion 真实源码**，本项目没有名为 Δds 的字段或变量）：

```text
# 概念伪代码：逐帧求 Δds 并判断运动方向
for i in range(len(rows) - 1):
    a = rows[i]
    b = rows[i + 1]
    if a.ds is None or b.ds is None:      # 任一端无效 → 无法比较
        delta_ds = None                   # 留空，不填 0，不插值
    else:
        delta_ds = b.ds - a.ds            # Δds

    if delta_ds is None:
        方向 = "未知（数据断开）"
    elif delta_ds > 0:
        方向 = "向正方向运动"
    elif delta_ds < 0:
        方向 = "向负方向运动"
    else:
        方向 = "该间隔读数不变（需结合数据判断）"
```

### 6.2 判据（概念解释）

| Δds 的符号 | 运动方向 | 说明 |
| --- | --- | --- |
| Δds > 0 | **向正方向运动** | 沿 `U` / `U_004`（P1 → P2）方向移动 |
| Δds < 0 | **向负方向运动** | 逆着 `U` / `U_004` 方向移动 |
| Δds = 0 | 该相邻间隔读数不变 | 可能是静止，也可能是采样点之间的往返刚好抵消；要看更多帧才能下结论 |

### 6.3 两个前提（与源码 / 数据结构直接相关）

1. **两帧都必须 valid。** `ds` 只在 `valid=True` 的行存在（第 338～340 行）；任何一端为空，Δds 就无法计算，也不能当成 0；
2. **不能跨空洞计算。** M4 静态数据的平台之间是长段 `valid=False`（第 7 节）；跨过这些空洞的"差值"不是连续运动，只是两个可测时刻之间的距离。Δds 只在相邻且都有效的帧之间才有运动方向意义。

### 6.4 Δds 不是速度（概念解释）

- Δds 是**位移的变化量**（px 或 mm）；
- 速度 = Δds / Δt（px/s 或 mm/s）——需要除以相邻两帧的时间间隔（本项目 30 fps，Δt = 1/30 s ≈ 0.033333 s）；
- 本项目**没有速度字段**，课程也不计算速度；本课只需要把 Δds 的**符号**读对。

### 6.5 与源码的关系（项目真实源码）

- 源码里**没有** `Δds` / `delta_ds` 这样的变量或 CSV 字段——它是本课为了讲清"方向判据"引入的**概念量**；
- 源码里把同一条规则写成文字：**"正向 = ds 增大……负向 = ds 减小"**（`src\dynamic_displacement.py` 第 83～84 行；模块 docstring 第 480～481 行也重复了这条规则）；
- `detect_turning_points()`（第 462 行起）实际使用的是**原始 `x_px` 序列**（第 467、495～497 行），不是 `ds`；因为 `U_004` 的 `ux > 0`，正向对应原始 x 增大（第 481 行）——这一步的完整逻辑属于 L12，本课只登记；
- 结论：**"Δds 判方向"是源码文字规则（第 83～84 行）的数学表达**，但它本身属于"概念解释"，不要引用成"源码里有 Δds 字段"。

## 9. 两个必须记住的真实例子（符号侧 ≠ 运动方向）

### 9.1 M5 frame 237 → frame 313：负侧，但向正方向运动

| frame | time_s | `s_px` | `ds_px` | `ds_mm` | 读法 |
| --- | --- | --- | --- | --- | --- |
| 237 | 3.941791 | 855.174 | −0.028 | **−0.0046** | 起点在**负侧**（几乎就在参考位置上） |
| 313 | 5.205826 | 1020.546 | 165.343 | **+27.1660** | 终点在**正侧** |

Δds = +27.1660 − (−0.0046) = **+27.1706 mm**（用 `ds_px` 算是 +165.371 px）→ **向正方向运动**。

只读核对补充：frame 237～313 之间 `ds_mm` **逐帧单调不减**（抽查 frame 238 = +0.0233、frame 239 = +0.4012、frame 312 = +27.1511）——整段都在往正方向走。

**结论**：起点 `ds < 0`（在负侧），运动方向却是正方向。**"在哪一侧"和"往哪边走"是两件独立的事。**

### 9.2 M5 frame 963 → frame 1015：正侧，但向负方向运动

| frame | time_s | `s_px` | `ds_px` | `ds_mm` | 读法 |
| --- | --- | --- | --- | --- | --- |
| 963 | 16.016646 | 1097.377 | 242.174 | **+39.7894** | 起点在**正侧**，且有约 40 mm 的距离 |
| 1015 | 16.881511 | 1014.415 | 159.212 | **+26.1587** | 终点仍在**正侧** |

Δds = +26.1587 − (+39.7894) = **−13.6307 mm**（用 `ds_px` 算是 −82.962 px）→ **向负方向运动**。

只读核对补充：frame 963～1015 之间 `ds_mm` **逐帧单调不增**（抽查 frame 964 = +39.5429、frame 965 = +39.0746、frame 1014 = +26.2916）——整段都在往负方向走。

**结论**：起点与终点 `ds` 都为正（都在正侧），运动方向却是负方向。再一次说明：**判断运动方向只看 Δds 的符号**。

### 9.3 两个例子的合起来读

| 例子 | 起点的 `ds` 符号 | Δds 的符号 | 运动方向 |
| --- | --- | --- | --- |
| M5 f237 → f313 | 负（−0.0046 mm） | 正（+27.1706 mm） | 向正方向 |
| M5 f963 → f1015 | 正（+39.7894 mm） | 负（−13.6307 mm） | 向负方向 |

四句话总结：

1. `ds` 的符号回答"在参考位置的哪一侧"；
2. `Δds` 的符号回答"正在往哪个方向运动"；
3. 两者可以任意组合（负侧向正、正侧向负、正侧向正、负侧向负）；
4. 符号本身不代表好坏或快慢。

## 14. 本课核心概念（16 条）

1. **`ds` 的正负只是位置方向记号**——表示这一帧落在参考位置 `s0` 的正侧还是负侧，不代表好坏、不代表快慢；
2. **`ds` 的大小表示离参考位置 `s0` 多远**——`|ds_px|` / `|ds_mm|` 是沿尺方向的投影距离，不是二维欧氏距离、不是速度；
3. **`ds` 的变化量 Δds 才表示正在往哪个方向运动**——判断方向看 Δds 的符号；
4. **Δds = ds[i+1] − ds[i]**（相邻两帧之差）；
5. **Δds > 0 = 向正方向运动**（沿 P1 → P2 方向）；
6. **Δds < 0 = 向负方向运动**（逆着 P1 → P2 方向）；
7. **VisionMotion 的正方向来自标定点 P1 → P2 的人为约定**——M4：10 cm → 16 cm（第 46、55 行）；M5：10 cm → 20 cm（第 66 行）；
8. **M4：10 cm → 16 cm**（第 46 行约定，第 55 行 `U`）；
9. **M5：10 cm → 20 cm**（第 66 行 `U_004`，第 83～84 行正向/负向定义）；
10. **`s0` 是参考位置，不带方向**——正负来自 `s_px` 与 `s0` 的相对关系（谁大谁小，第 339 行）；
11. **`valid=False` 时 `s_px` / `ds_px` / `ds_mm` 均留空**（第 272～274、284～285、338～340、360～363 行）——不写 0 / −1 / nan；Δds 在空洞处断开；
12. **M4 静态数据的形态是"平台 + 台阶 + 空洞"**——7 个平台（约 0、10、20、30、40、50、60 mm），台阶间隔约 10 mm，平台之间是 valid=False 的空洞；
13. **M5 动态数据的形态是"连续往返"**——1766/1766 全部有效、无空洞；`ds_mm` 从 −0.5283（frame 0）到 66.1663（frame 1701），数值多次上升、下降；
14. **真实例子（负侧向正运动）**：M5 frame 237 → 313，`ds_mm` 从 −0.0046 增大到 +27.1660（Δds = +27.1706 mm）；
15. **真实例子（正侧向负运动）**：M5 frame 963 → 1015，`ds_mm` 从 +39.7894 减小到 +26.1587（Δds = −13.6307 mm）；
16. **`MIN_TURN_TRAVEL_PX = 20.0` 的最小认识**（第 87 行）：反向行程阈值——从当前极值反向走满 20 px 才承认转向；作用是抗静止段噪声；完整算法属于 L12；
17. **L10 → L11 → L12 的知识连接**：L10 算出位移 → L11 建立符号 / 方向读法 → L12 进入转向点、峰谷与运动段；

## 15. 易错点

1. **把 `ds` 的正负当成好坏。** 负号只是"在参考位置的负侧"；三份真实数据里负号帧（34 / 18 / 161）都是正常测量结果（第 4.4 节）。
2. **把 `ds` 的大小当成快慢。** `|ds|` 是距离，不是速度；0 → 60 mm 用 1 秒还是 10 秒，`|ds|` 完全一样。
3. **用 `ds` 的符号判断运动方向。** 方向要看 Δds：M5 f237 在负侧却向正运动、f963 在正侧却向负运动（第 9 节）。
4. **以为 `ds` 为正就"一定在向前"、为负就"一定在后退"。** "前 / 后"必须绑定方向约定（P1 → P2）；换一个约定会全部反号。
5. **把 `s0` 当成"带方向的量"。** `s0` 是参考位置（一个位置坐标）；方向来自 `U` / `U_004` 的约定，符号来自 `s_px` 与 `s0` 的相对大小。
6. **跨空洞计算 Δds。** M4 的平台之间是长段 valid=False；跨洞的差值不是连续运动，只是两个可测时刻之间的距离（第 6.3、7.5 节）。
7. **把 Δds 当速度。** Δds 是位移变化量；速度需要除以 Δt，本项目不做这件事。
8. **以为 Δds 是源码里的字段。** 源码没有 `Δds` / `delta_ds`；只有"正向 = ds 增大 / 负向 = ds 减小"的文字规则（第 83～84、480 行）。Δds 是概念量。
9. **把"正 / 负 / 零"计数当成"运动方向统计"。** 1016/34/0 等计数统计的是**符号侧**（`ds_mm` 非空行），不是"有多少帧在向正方向运动"。
10. **把"零 0 例"理解成"不可能经过参考位置"。** 它只说明这三份文件的 4 位小数里没有恰好为 0.0000 的行；`ds = 0` 的概念仍然存在（`s_px = s0`）。
11. **把静态数据的空洞当成"数据错误"或"需要插值补齐"。** 空洞是 `valid=False` 的合法表达（不删行、留空）；补齐会伪造数据（L10 已学）。
12. **把 M4 / M5 的正方向约定混起来用。** 10 → 16 cm 与 10 → 20 cm 是两套常量（第 55 / 66 行），不能互换。
13. **以为"负号集中在开头"是数据缺陷。** STATIC 的负号都在第一个平台（frame 1～51 / 2～34）、M5 的负号都在 frame 0～237——它们是真实的参考位置附近波动。
14. **在 L11 就急着学完整转向点算法 / 运动段 / 周期 / 频率 / FFT。** 本课只到"符号、大小、Δds 方向判据、`MIN_TURN_TRAVEL_PX` 最小认识"。
15. **把教学示例当真实数据。** 第 6.6 节的 `+30.0 → +27.0 mm` 是编出来的算例；项目数字只以 `results\` 下的真实行为准。
16. **把概念伪代码当源码。** 第 6.1、10.2 节的伪代码是流程示意；真实源码只有第 272～274、284～285、338～340、360～363 行那些语句。
