## 3. 位置 ≠ 位移：s_px 与 ds_px

### 3.1 四个量各自的定义

| 量 | 定义 | 单位 | 回答的问题 | 源码 |
| --- | --- | --- | --- | --- |
| `s_px` | 二维像素坐标 `(x_px, y_px)` 在方向 `u` 上的一维投影坐标（L09） | px | "沿尺方向现在在哪？" | M4 第 277～285 行；M5 第 286～294 行 |
| `s0` | 前 `window_s` 秒内 valid=True 帧的 `s_px` 平均值（本课） | px | "起点基线在哪？" | M4 第 288～325 行；M5 第 297～335 行 |
| `ds_px` | `s_px - s0` | px | "相对基线走了多少？" | M4 第 339 行；M5 第 349 行 |
| `ds_mm` | `ds_px / PX_PER_MM` | mm | "相对基线走了多少毫米？" | M4 第 340 行；M5 第 350 行 |

### 3.2 为什么 position ≠ displacement

1. **位置有"零点从哪来"的问题，位移没有。** `s_px` 的零点由图像原点 `(0, 0)` 与方向 `u` 共同决定（L09）；换一个方向常量或换一段视频，`s_px` 的绝对值会整体平移。位移是两个时刻之差，与原点选取无关。
2. **`s_px` 的绝对值不能跨实验比较，差值可以。** 同一个二维点在两次实验里可以有完全不同的 `s_px`；但"沿尺方向从 A 到 B 走了多少"是可比较的。
3. **只有位移才直接对应物理问题。** "相对开始时移动了多少"必须写成差值 `ds_px = s_px - s0`，而不是把 `s_px` 当成"起点为 0 的距离"。

一个教学示例（**非项目数据**）：若某段数据里 `s_px` 从 1080.4 变到 1075.6，直接读 `s_px` 只能说"位置坐标从 1080.4 变到 1075.6"；减去基线（`s0 = 1076.06`）之后才能说"位移从 `+4.34 px` 变到 `-0.46 px`"。真实数据里的 frame 0 正是这种情况（见第 5.7 节）。

## 5. s0：基线的定义

### 5.1 compute_s0() 的定义

M4（`src\displacement.py` 第 288～325 行）：

```python
# src\displacement.py 第 288 行（函数签名）与第 290～295 行（docstring 摘要，节选）
def compute_s0(rows, window_s=S0_WINDOW_S, min_valid_frames=MIN_S0_VALID_FRAMES):
    """
    第 4 / 5 步：收集前 window_s 秒内 valid=True 的 s_px，并计算 s0。

    s0 = 只使用 time_s <= window_s 且 valid=True 的帧，取这些帧 s_px 的平均值。

    正式禁止：用 10 cm 代替 s0、用首帧代替均值、扩大窗口、
              插值、平滑、预测、按分位数自动调整。
    """
```

一句话定义：

> **`s0` = 时间窗口（`time_s <= window_s`）内所有 `valid=True` 帧的 `s_px` 平均值。**

### 5.2 逐行展开（M4 第 304～323 行 / M5 第 314～333 行）

```python
# src\displacement.py 第 304～305 行（原文）
    window_rows = [row for row in rows if row["time_s"] <= window_s]
    valid_s_values = [row["s_px"] for row in window_rows if row["valid"]]
```

- 第 304 行：只挑 `time_s <= window_s` 的行（**闭区间**，包含边界）；
- 第 305 行：在这些行里只留 `valid=True` 的 `s_px`——这是第二道筛选真正生效的地方之一。

`compute_s0()` 返回一个"报告字典"（第 307～320 行），字段包括：`window_s`、`window_total_frames`（窗口总帧数）、`window_valid_frames`（窗口有效帧数）、`window_missed_frames`（窗口内 detected=False 数量）、`window_detected_invalid_frames`（窗口内 detected=True 但 valid=False 数量）、`min_valid_frames`、`ok`、`s0`。

```python
# src\displacement.py 第 318 行（原文）
        "ok": len(valid_s_values) >= min_valid_frames,

# src\displacement.py 第 322～323 行（原文）
    if report["ok"]:
        report["s0"] = sum(valid_s_values) / float(len(valid_s_values))
```

- 第 322～323 行：**平均值**——`sum / 个数`。

### 5.5 为什么 s0 不是首帧

1. **源码把"用首帧代替均值"列为正式禁止项**（第 294 行原文"正式禁止：……用首帧代替均值"）；
2. **均值抗单帧噪声**：单帧的 `s_px` 可能受检测噪声与运动瞬间影响，窗口内几十帧的平均更稳；
3. **首帧也可能是坏帧**（甚至 valid=False）——如果恰好用首帧当基线，会把一帧的偶然误差变成整段数据的系统偏移；
4. 真实数据直接证明二者不同：STATIC-002 的 `s0 = 1076.063871 px`，而 frame 0 的 `s_px = 1080.399 px`，相差 `+4.335 px`（见第 5.7 节）。

### 5.6 为什么 s0 不是标尺 10 cm 位置

- 标尺 10 cm 刻线是**标定点 P1 的现实位置**：M4 的 P1 像素坐标是 `(1036.23, 490.58)`（第 44 行），M5 的 P1 是 `(813.50, 296.49)`（M5 第 60 行）——它们回答的是"标定时 10 cm 刻线出现在画面的哪里"；
- `s0` 是**每个视频自己的数据基线**：前 0.5 s（M4）/ 前 2.0 s（M5）内 valid 帧 `s_px` 的平均值；
- 两者的来源、对象、数值都不同。只读复算（把冻结标定点代入同一投影公式）：M4 的 `s(P1) ≈ 1032.823 px`、`s(P2) ≈ 1378.242 px`；M5 的 `s(P1) ≈ 812.334 px`、`s(P2) ≈ 1420.968 px`——它们都不是对应视频的 `s0`（1076.063871 / 1077.364097 / 855.202603 px）；
- 源码第 294 行明文"**正式禁止：用 10 cm 代替 `s0`**"；
- 为什么不干脆规定"位移从 10 cm 刻度算起"？因为刻度线只是**标定用的参考点**：它在画面里的投影值由标定流程确定（M5 第 59 行写明"人工点击 + 独立核验"），代表"这把尺的 10 cm 刻度在画面里出现在哪"，而不是"这段视频开始时目标在哪"；`s0` 直接用这批数据自身开头窗口的有效测量，回答的才是后者。两者用途不同，不能互相代替。

### 5.7 为什么第 0 帧的 ds_px 不一定为 0

因为 `ds_px = s_px - s0`，而 `s0` 是**窗口内均值**，不是 frame 0 的值。只有当 frame 0 的 `s_px` 恰好等于窗口均值时，它的 `ds_px` 才是 0；这是巧合，不是规则。三份真实数据的 frame 0：

| 文件 | frame 0 的 `s_px` | `s0`（复算） | frame 0 的 `ds_px` | 说明 |
| --- | --- | --- | --- | --- |
| `results\EXP-003-STATIC-002_ds.csv` | 1080.399 | 1076.063871 | **+4.335** | 不为 0 |
| `results\EXP-003-STATIC-003_ds.csv` | 1077.528 | 1077.364097 | **+0.164** | 不为 0（很小） |
| `results\EXP-004-DYNAMIC-001_ds.csv` | 851.987 | 855.202603 | **-3.215** | 不为 0 |

三个例子刚好覆盖三种情形：明显为正、接近 0 但不为 0、明显为负。**不要用"第 0 帧 `ds_px` 应该是 0"去检查数据**——正确检查是"`ds_px = s_px - s0`"（第 8.3 节）。

## 6. ds_px 与 ds_mm：位移公式

### 6.1 add_displacement()（M4 第 328～340 行 / M5 第 338～350 行）

```python
# src\displacement.py 第 328～340 行（原文）
def add_displacement(rows, s0):
    """
    第 6 步：valid=True 的行计算 ds_px / ds_mm。

        ds_px = s_px - s0
        ds_mm = ds_px / PX_PER_MM

    valid=False 的行保持 None（写 CSV 时留空），绝不填 0。
    """
    for row in rows:
        if row["valid"]:
            row["ds_px"] = row["s_px"] - s0
            row["ds_mm"] = row["ds_px"] / PX_PER_MM
```

M5 版本（第 338～350 行）唯一区别是除数：`row["ds_mm"] = row["ds_px"] / PX_PER_MM_004`（第 350 行）。

### 6.2 公式与单位

数学公式（源码是它们的实现）：

```text
ds_px = s_px - s0                 [px - px = px]        （第 339 / 349 行）
ds_mm = ds_px / PX_PER_MM         [px ÷ (px/mm) = mm]   （第 340 行）
       = ds_px × MM_PER_PX        [px × (mm/px) = mm]   （等价写法）
```

- M4 的 `PX_PER_MM = 5.756961`（第 52 行）、`MM_PER_PX = 0.173703`（第 53 行）；M5 的 `PX_PER_MM_004 = 6.086399`（M5 第 64 行）；
- 把除法写成乘法（乘反）会差约 33 倍：`5.756961² ≈ 33.14`；
- 把 M5 的尺度用到 M4（或反过来）会系统性偏约 5.72%（`6.086399 / 5.756961`）。

### 6.3 写 CSV：小数位与空值

`build_ds_row()`：M4 第 348～366 行 / M5 第 358～376 行；小数位规范来自 `FIELD_PATTERNS`（M4 第 84～90 行 / M5 第 103～109 行）：

| 字段 | 小数位 | 正则（原文） |
| --- | --- | --- |
| `time_s` | 6 | `^-?\d+\.\d{6}$` |
| `s_px` | 3 | `^-?\d+\.\d{3}$` |
| `ds_px` | 3 | `^-?\d+\.\d{3}$` |
| `ds_mm` | 4 | `^-?\d+\.\d{4}$` |
| `area_px` | 1 | `^-?\d+\.\d{1}$` |

注意：**`ds_mm` 是用未舍入的 `ds_px` 计算后再舍入到 4 位小数的**，而 `ds_px` 写入文件时只有 3 位小数——这就是"双重舍入"（L08 已登记，本课用真实数字复核，见第 8.4 节）。

## 13. 本节课最重要的概念

1. **`s_px` 是位置，`ds_px` 是位移**：`s_px` 回答"沿尺方向在哪"，`ds_px = s_px - s0` 回答"相对基线走了多少"；
2. **位置 ≠ 位移的三条理由**：零点来源不同、绝对值不可跨实验比较、只有差值对应物理位移；
3. **valid 是第二道数据筛选**：`detected`（M3）→ `valid`（本模块 gate）→ `s_px` → `ds_px` → `ds_mm`；
4. **M4 valid 门限**：detected=True 且 `2000 <= area_px <= 15000` 且 `400 <= y_px <= 540`（第 57～64、175～201 行）；
5. **M5 valid 门限**：detected=True 且 `4500 <= area_px <= 6500` 且 `200 <= y_px <= 250`（M5 第 68～76、183～210 行）；
6. **无效帧不删除**：行数与 track CSV 一致；`s_px` / `ds_px` / `ds_mm` 留空、`valid=False`；绝不写 0 / -1 / nan（第 21～22、265～274、355～363 行）；
7. **`s0` 的定义**：时间窗口内（`time_s <= window_s`）所有 valid=True 帧的 `s_px` 平均值（第 290～295、304～305、322～323 行）；
8. **M4 的 s0 参数**：`S0_WINDOW_S = 0.5`、`MIN_S0_VALID_FRAMES = 10`（第 66～68 行）；
9. **M5 的 s0 参数**：`S0_WINDOW_S = 2.0`、`MIN_S0_VALID_FRAMES = 60`（M5 第 78～80 行）；
10. **`s0` 不是首帧**：源码明文禁止"用首帧代替均值"（第 294 行）；真实数据里 frame 0 的 `ds_px` = +4.335 / +0.164 / −3.215；
11. **`s0` 不是 10 cm 位置**：10 cm 是标定点 P1 的现实位置（第 44 / M5 第 60 行），`s0` 是数据窗口的平均值；源码明文禁止"用 10 cm 代替 `s0`"（第 294 行）；
12. **`s0` 不达标不写 ds CSV**：`ok=False` 时不写（第 781、793 行 / M5 第 1159、1171～1174 行）；处理原则是"不扩大窗口、不修改阈值、不做插值"（第 517 行）；
13. **位移公式**：`ds_px = s_px - s0`（第 339 / 349 行）；`ds_mm = ds_px / PX_PER_MM`（第 340 行，M5 用 `PX_PER_MM_004`，第 350 行）；等价 `ds_px × MM_PER_PX`；
14. **真实数据验证**：三份 ds CSV 的 `s0` = 1076.063871 / 1077.364097 / 855.202603 px；`ds_px` 复算最大偏差 ≤ 0.000904 px；`ds_mm` 复算最大偏差 ≤ 0.000151 mm（都在自检容差内）；
15. **双重舍入**：`ds_mm` 由未舍入的 `ds_px` 算出再写 4 位小数；用文件里的 3 位 `ds_px` 反算可能出现 ~1e-4 mm 的差——正常；
16. **M4 与 M5 参数不能混用**：尺度、gate、`s0` 窗口、方向全部不同；源码结构性禁止（M5 第 20～23、68 行）；
17. **"检测到"不等于"可用于物理计算"**：detected=True 但 valid=False 的帧在 STATIC-002 / STATIC-003 里分别有 911 / 792 个；
18. **统计口径**：`valid_rate`（第 420 / 437 行）、`invalid_count`（第 421 / 438 行）、`detected_invalid_count`（第 423 / 440 行）、`longest_invalid_run`（第 427 / 450 行）；
19. **数据依赖链**：`detected → valid → s_px → ds_px → ds_mm`，每一环只依赖上一环；
20. **L09 → L10 → 后续**：坐标 → 位移 → 峰值 / 谷值 / 转向点 / 周期 / 频率 / FFT（后续课程）；
21. **五类材料**：真实源码 / 真实数据 / 数学公式 / 教学示例 / 概念伪代码（第 11 节）。

## 14. 易错点

1. **把 `s_px` 当位移用。** `s_px` 是位置坐标；位移必须减去基线：`ds_px = s_px - s0`（第 339 行）。看 `s_px` 曲线谈"幅值"之前先问"基线在哪"；
2. **以为第 0 帧的 `ds_px` 一定是 0。** `s0` 是窗口均值；真实数据里 frame 0 的 `ds_px` = +4.335 / +0.164 / −3.215（第 5.7 节）；
3. **用首帧代替 `s0` 重算数据。** 源码明文禁止（第 294 行）；用首帧做基线会让全部 `ds` 整体平移；
4. **把标尺 10 cm 位置当基线。** 刻度线是标定点（第 44 行 / M5 第 60 行），`s0` 是数据窗口均值；两者来源不同，源码明文禁止互相代替（第 294 行）；
5. **把 detected 当 valid。** detected=True 只表示"检测到了"；STATIC-002 有 911 帧 detected=True 但 valid=False（第 4.5 节）；只看 detected 成功率会严重高估可用数据量；
6. **把无效帧从 CSV 里删掉或填 0。** 规则是"不删除、留空"（第 21～22、355 行）；填 0 会把"没测到"伪造成"位移等于 0"；填上一帧坐标 / 插值同样禁止；
7. **以为"valid=False 的行没有行号 / 被跳过"。** 行还在（行数与 track CSV 相同），只是位移字段为空、`valid=False`；
8. **混用 M4 与 M5 的 gate。** 阈值是为各自拍摄几何定制的（第 57 行注释）；M5 第 68 行明文"不得混用"。混用不会报错：EXP-004 的 y（208.63～220.61）在 M4 的 y 门限（400～540）下会被全部拒绝；
9. **混用 M4 与 M5 的尺度常量。** `5.756961` 与 `6.086399` 相差 5.72%；`src\dynamic_displacement.py` 第 20～23 行禁止 import 来从结构上防止这件事；
10. **混用两套 `s0` 参数。** 0.5 s / 10 帧与 2.0 s / 60 帧都是拍板值；改窗口或降门槛都属于"改规则"，不是"修数据"（第 517 行明确不这么做）；
11. **用文件里已舍入的 `ds_px` 反算 `ds_mm`，看到 ±0.0001 就以为错了。** 双重舍入所致，容差 0.0005 mm（第 736、740 行 / M5 第 1108、1113 行）；
12. **以为 `s0` 是"这段位移的平均"。** `s0` 平均的是 `s_px`（位置），不是 `ds`；窗口内先做 valid 筛选，再对位置求平均；
13. **把 `s0` 的容差与含义记错。** `s0` 复算容差是 0.002 px（第 715 行 / M5 第 1085 行）；`s0` 本身是完整精度，不是 CSV 里的舍入值；
14. **把"检测到"当成"可以算物理量"。** 物理计算链的入口是 valid=True；detected 只是第一道门；
15. **在 L10 就急着学峰值 / 谷值 / 周期 / 频率 / FFT。** 这些是后续课程；本课只到"位移数据 `ds_px` / `ds_mm` 已经算好并验证"为止；
16. **把教学示例当真实数据。** 第 3.2、8 节的算术例子与推演是教学材料；项目数字只以 `results\` 下真实行为准（第 11 节）。

> L10 把 L09 的"一维位置"变成了"位移"：track CSV 进入本模块后，第一条规则是 **valid gate**（`is_valid_frame()`，`src\displacement.py` 第 175～201 行）——只有 `detected=True` 且 `2000 <= area_px <= 15000` 且 `400 <= y_px <= 540` 的帧（M4）才算 valid；M5 的专属 gate 是 `4500 <= area_px <= 6500` 且 `200 <= y_px <= 250`（`src\dynamic_displacement.py` 第 68～76 行）——**"检测到"不等于"可用于物理计算"**。第二条规则是 **`s0`**（`compute_s0()`，第 288～325 行）：只取 `time_s <= 0.5`（M4）或 `<= 2.0`（M5）且 `valid=True` 的帧，对它们的 `s_px` 求平均（第 304～305、322～323 行），并且要求至少 10 / 60 帧（第 318 行），不达标就不写 ds CSV（第 781、793 行）——**`s0` 不是首帧，也不是标尺 10 cm 位置**。第三条规则是位移公式：`ds_px = s_px - s0`（第 339 行）、`ds_mm = ds_px / PX_PER_MM`（第 340 行；M5 用 `PX_PER_MM_004`，第 350 行）。无效帧不删除、位移字段留空（第 21～22、355、360～363 行）。真实数据给出闭环：STATIC-002（1961 行，valid 1050/911，`s0` = 1076.063871 px）、STATIC-003（1984 行，valid 1192/792，`s0` = 1077.364097 px）、EXP-004（1766 行，全部 valid，`s0` = 855.202603 px）——三份文件的 `ds_px` 复算最大偏差 ≤ 0.000904 px、`ds_mm` 复算最大偏差 ≤ 0.000151 mm，全部落在自检容差（0.002 px / 0.0005 mm）内；frame 0 的 `ds_px` 分别是 +4.335 / +0.164 / −3.215 px，直接证明"第 0 帧 `ds_px` 不一定为 0"。下一步（峰值 / 谷值、转向点、周期 / 频率 / FFT）属于后续课程，本课不展开。
