## 4. 为什么需要转向点检测

### 4.1 L11 已经走到哪一步（概念解释 + 源码依据）

`src\dynamic_displacement.py` 第 83–84 行把方向规则写成两句：

- **正向 = `ds` 增大（沿 `U_004`，即尺子 10 cm → 20 cm 方向）**；
- **负向 = `ds` 减小**。

L11 由此得到：**Δds 变号 ⇔ 运动方向改变**。
但 Δds 只是一个"逐帧比较"的判据：它告诉你"相邻两帧之间"读数是在变大还是变小，**不直接告诉你"哪一帧是转向点"**。

### 4.2 为什么不能"看到一帧变大/变小就认定转向"

程序不能简单地"这一帧比上一帧小 → 转向了"，原因有三条（**概念解释**；其中噪声数字来自源码第 476 行的冻结说明）：

1. **噪声**：测量值会有抖动。源码第 476 行给出的冻结说明是：本视频静止段相邻帧 |dx| 中位数约 0.13 px、静止段最大约 1.25 px。若"一帧变小"就算转向，静止段里随机的上下抖动会制造大量**假转向**；转向点会变成噪声的产物，而不是运动的产物。
2. **极值平台**：真实到达极值附近时，测量值可能在若干帧内几乎不变（平台）。"第一个开始变小的帧"可能落在平台的任意位置，甚至来自一次抖动；它不等于"真正的极值帧"。因此需要"持续更新极值 + 反向走满一定行程才确认"的规则。
3. **可复现性**：如果规则是"看起来这里转向了"，不同人、不同时间会得到不同结果。项目要求把规则**冻结**成明确常量与确定流程：同一个输入 → 同一个输出，任何人都能按行号审计。

### 4.3 转向点检测要回答的两个问题（概念解释）

- **在哪一帧转向？** → 由 `extreme_index` 记录"当前方向上的极值位置"；
- **什么时候确认这次转向？** → 由"从该极值反向走满 20 px"的那一帧确认。

把这两件事分开，是 L12 最重要的设计。若把它们合成一件事，就会把"确认帧"误当成"转向帧"（见第 8 节）。

### 6.2 `direction == 0`：如何确定初始方向（第 550–553 行）

```python

读法：

- 方向还没确定时，先看当前位置 `x_i` 相对当前极值 `x_extreme` 的**距离绝对值**是否达到 20 px；

            if x_i < x_extreme:
                extreme_index = i
            elif x_i - x_extreme >= MIN_TURN_TRAVEL_PX:
                turn_indexes.append((extreme_index, "valley"))
                direction = 1
                extreme_index = i
```

读法与 `direction == +1` 完全镜像：

- **还在往 −x 走**（`x_i < x_extreme`）→ 极值更新为 `i`（第 533–534 行）；
- **开始反向**（`x_i >= x_extreme`）→ 检查 `x_i - x_extreme`；
- 反向行程 **≥ 20 px**（第 564 行）才把 `(extreme_index, "valley")` 写入 `turn_indexes`（第 565 行）——写入的仍是 `extreme_index`（谷值所在帧）；
- 确认后方向翻到 `+1`（第 566 行），`extreme_index` 重置为 `i`（第 567 行）。

### 6.5 状态机的三条纪律（概念解释）

1. **没有"未来信息"**：循环只看 `series[0..i]` 与当前极值，不用后续帧、不做拟合、不做预测；
2. **帧序号记账，不做插值**：转向点落在某个具体 frame 上（`extreme_index`），不会"落在两帧之间"；
3. **确认是累计行程，不是单帧变化**：只要反向行程还没到 20 px，就继续保留当前极值；到了才确认。这样小的噪声抖动不会触发转向。

概念伪代码（**不是 VisionMotion 真实源码**；只是把第 541–567 行的流程改写成教学版本）：

```text
# 概念伪代码：zigzag 状态机
turn_indexes = []        # 已确认转向点
direction = 0            # 0 / +1 / -1
extreme_index = 0        # 当前方向上的极值

for i in 1 .. len(series)-1:
    x_i = series[i].x_px
    x_e = series[extreme_index].x_px

    if direction == 0:
        if |x_i - x_e| >= 20:
            direction = +1 if x_i > x_e else -1
            extreme_index = i
    elif direction == +1:
        if x_i > x_e:
            extreme_index = i
        elif x_e - x_i >= 20:
            turn_indexes.append((extreme_index, "peak"))
            direction = -1
            extreme_index = i
    else:                # direction == -1
        if x_i < x_e:
            extreme_index = i
        elif x_i - x_e >= 20:
            turn_indexes.append((extreme_index, "valley"))
            direction = +1
            extreme_index = i
```

## 8. 极值与确认帧的区别（本课最重要的概念）

### 8.1 源码是怎么写的（项目真实源码）

- 第 558 行：`turn_indexes.append((extreme_index, "peak"))` —— 追加进列表的第一个元素是 **`extreme_index`**；
- 第 565 行：`turn_indexes.append((extreme_index, "valley"))` —— 同样是 **`extreme_index`**；
- 第 583 行：`item = describe(series[index])` —— 输出时取的是 `series[index]`，其中 `index` 就是上面的 `extreme_index`；
- 而"反向走满 20 px"的那一帧是循环变量 `i`，它只用来**触发确认**（以及第 560、567 行把 `extreme_index` 重置为 `i`），**不会写进 `turn_indexes` 作为转向帧**。

一句话：**转向点存的是极值帧；确认帧只是"这笔转向被程序承认"的时刻，比转向点晚。**

### 8.2 本课讲解的三个真实案例（真实数据）

| 转向点（极值帧） | kind | 极值帧 x_px | 确认帧 | 确认帧 x_px | 反向行程 |
| --- | --- | --- | --- | --- | --- |
| f491 | peak | 1057.86 | **f505** | 1036.15 | 1057.86 − 1036.15 = **21.71 px** |
| f602 | valley | 973.06 | **f732** | 995.34 | 995.34 − 973.06 = **22.28 px** |
| f838 | peak | 1099.23 | **f971** | 1078.52 | 1099.23 − 1078.52 = **20.71 px** |

读法（以 peak f491 → f505 为例）：

- f491 是"这一轮正向运动的最高点"（局部极大），程序把它记为转向点；
- 从 f491 之后，测量值一路回落；直到 **f505**，回落幅度第一次达到 20 px（21.71 px），程序才承认"f491 这里确实转向了"；
- 所以 **f491 是转向点，f505 是确认帧**。两者相差 14 帧（f505 − f491 = 14）；对应的时间差直接由 CSV 时间列相减得到：8.399176 − 8.166327 = **0.232849 s**。这不是 bug，而是"抗噪 + 可复现"必须付出的确认滞后。
- 换算提示（概念解释）："帧数 ↔ 秒"一律以该视频 CSV 的 `time_s` 为准；项目里不同阶段视频的帧率可能不同（L01 学的 30 fps 是那一段外部视频的例子），不要拿一个固定帧率去套所有数据。

| 结果去向 | 决定 `turn_indexes` 是否新增一个转向点 | 决定该 `segment` 的 `below_min_travel` 是 `True` 还是 `False` |

两处虽然都写 20 px，但**比较对象不同**：一个是"从极值反向的**局部**行程"，另一个是"整段边界之间的**整体**行程"。把两者混为一谈，是 L12 最容易犯的概念错误之一。

## 14. 工程思想：为什么坚持保留原始数据、不平滑、不插值、不补帧、不预测

### 14.1 源码里的边界（项目真实源码）

| 行号 | 原文要点 |
| --- | --- |
| 第 16 行 | 数据链最后一步："原始 x_px 转向点统计（最小反向行程 20 px，不平滑、不滤波）" |
| 第 27 行 | "不删除任何 track CSV 行；valid=False 的位移字段一律留空（不写 0 / -1 / nan）" |
| 第 28 行 | "不做平滑 / 滤波 / 插值 / 补帧 / 补零 / 预测 / FFT / 频率 / 周期 / 振幅分析" |
| 第 30 行 | "转向点只使用原始 x_px 数据，最小运动行程 MIN_TURN_TRAVEL_PX = 20.0 px" |
| 第 467–468 行 | 只使用原始 x_px；不平滑、不滤波、不插值、不补帧、不预测 |
| 第 503–506 行 | 20 px 反向行程阈值；用明确阈值抵抗静止段噪声 |

### 14.2 这些边界的工程含义（概念解释）

1. **原始数据是唯一证据。** 平滑、滤波、插值、拟合都会**改变数据本身**；一旦改了，后面所有结论都无法追溯回"哪一行原始 CSV"。保留原始数据，才能让每个转向点、每个段都能被逐行复算。
2. **噪声要用明确规则处理，而不是用数据处理掩盖。** 本项目的做法不是"把曲线修漂亮"，而是：允许噪声存在，用"反向走满 20 px 才确认"的明确规则把噪声挡在转向确认之外。这样，噪声仍然留在数据里，无法伪造一个转向点。
3. **可复现、可审计。** 阈值（20.0）是常量、算法是确定的循环、输入顺序固定（frame 升序）。同一个输入 → 同一个输出；报告会打印分析行数、invalid 行数、每个转向点、每个运动段，任何人可以按行号审计。
4. **职责单一、单一来源。** 检测只来自 `marker_detector.py`（由 M3 调用）；投影只来自 `src.calibration.project_point()`（第 40 行导入、第 26 行说明不重新实现）；M5 模块不得 `import src.displacement`（第 20–23 行），从结构上防止误用 M4 的 gate 与常量。
5. **边界清晰、先做什么后做什么。** 第 28 行把"FFT / 频率 / 周期 / 振幅"明确排除在外：先把转向点与运动段做扎实，后续课程才谈周期、频率与频谱。
6. **缺失与失败如实记录。** `valid=False` 的行不删除、位移字段留空；`ds_mm` 为 `None` 时打印"无"，不伪造数值（第 546、751、760、785–787 行）。"宁可报告缺测，也不改规则硬凑"。

## 16. 本课核心概念（18 条）

1. **转向点检测要解决"程序怎样自动、可复现地确定哪一帧是转向点"**——不能靠"这一帧比上一帧小"这种一帧判据；
2. **一帧判据不成立的三条原因**：噪声（静止段相邻帧 |dx| 中位数约 0.13 px、最大约 1.25 px，第 476 行）、极值平台、可复现性要求；
3. **输入是原始 `x_px` 序列**（`detected=True` 且 `x_px` 非空、按 frame 升序；第 467、524–526 行）；不使用 `s_px` / `ds`，不读平滑曲线；
4. **不平滑、不滤波、不插值、不补帧、不预测**（第 497 行；模块第 28 行）；
5. **`valid=False` 的行只统计、不删除**（第 527 行；第 514 行"只统计，不删除"）；它们仍留在分析序列里参与检测；
6. **状态机三个变量**：`turn_indexes`（第 542 行）、`direction`（第 514 行：0 / +1 / −1）、`extreme_index`（第 544 行）；
7. **`direction == 0`**：`|x_i − x_extreme| ≥ 20` 时确定方向（谁大往谁的方向），并把 `extreme_index` 移到 `i`（第 550–553 行）；
8. **`direction == +1`**：`x_i > x_extreme` 时更新峰值；`x_extreme − x_i ≥ 20` 时确认 peak 并翻转到 −1（第 554–560 行）；
9. **`direction == −1`**：镜像处理，`x_i < x_extreme` 时更新谷值；`x_i − x_extreme ≥ 20` 时确认 valley 并翻转到 +1（第 561–567 行）；
10. **`MIN_TURN_TRAVEL_PX = 20.0` 是反向行程阈值**（第 87、503–506 行）：只有从当前极值反向走满至少 20 px，该极值才算转向点；
11. **`turn_indexes` 存的是 `extreme_index`（转向点 / 极值帧），不是确认帧 `i`**（第 558、536 行）；确认帧只触发确认，随后 `extreme_index` 被重置为 `i`（第 531、567 行）；
12. **确认滞后是正常的**：真实案例 peak f491 → f505 确认、valley f602 → f732 确认、peak f838 → f971 确认；这是抗噪与可复现的代价；
13. **peak = 正向 → 负向**（第 558 行），**valley = 负向 → 正向**（第 536 行）；因为 `ux > 0`，peak 也是 `ds` 的局部极大、valley 也是 `ds` 的局部极小（第 509–510 行）；
14. **`turns` 有七个字段**：`frame` / `time_s` / `x_px` / `ds_mm`（`describe()` 第 569–576 行）+ `kind` / `direction_before` / `direction_after`（第 555–561 行）；`direction_before` / `direction_after` 由 `kind` 推导，不是再次测量；
15. **`segments` 用 `boundary_indexes = [0] + 所有转向点 + [len(series) − 1]` 切分**（第 595 行）；每段记录 start/end frame、time、x、direction、`travel_px`（第 600 行）、`below_min_travel`（第 617 行）；
16. **段数 = 转向点数 + 1**（第 479 行）；首帧和末帧只作为边界，不是转向点（第 507–508 行）；
17. **两种 20 px 比较对象不同**：转向确认比较"从极值反向的行程"（第 557、564 行）；`below_min_travel` 比较"整段两端之间的行程"（第 600、617 行）；
18. **EXP-004 真实结果**：6 个转向点（491 peak、602 valley、838 peak、1063 valley、1254 peak、1513 valley）、7 个运动段（205.05 / 84.80 / 126.17 / 92.22 / 190.09 / 128.80 / 188.61 px），与 `demo\run_m53_plot.py` 第 67–74 行冻结的 6 个 frame 完全一致；本课不展开周期、频率、频谱（FFT）。

## 17. 易错点（与 `COURSE_MISTAKES.md` 的 L12 条目对应）

1. **看到一帧变小/变大就认定转向。** 静止段噪声（约 0.13 px 中位数、约 1.25 px 最大）会制造假转向；必须用"反向走满 20 px"的规则；
2. **把 20 px 当成"相邻两帧差值"阈值。** 它是"从当前极值起的反向累计行程"；
3. **混淆两种 20 px。** 转向确认比的是"从极值反向的行程"（第 557、564 行）；`below_min_travel` 比的是"整段两端行程"（第 617 行）；
4. **把确认帧当转向点。** 转向点存 `extreme_index`；f491 在 f505 才确认、f602 在 f732 才确认、f838 在 f971 才确认；
5. **以为极值平台是数据错误。** 平台是真实采样结果；状态机持续更新极值，直到反向 20 px 才确认；
6. **删除 `valid=False` 的行，或把"统计 invalid"当成"删除数据"。** 第 527 行只统计；这些行仍留在分析序列里参与检测；
7. **用 `ds` / `s_px` / 平滑曲线做转向检测。** 第 467、524–526 行明确只用原始 `x_px`；
8. **做平滑 / 滤波 / 插值 / 补帧 / 预测。** 模块第 28 行明确禁止；
9. **把起点 / 终点当转向点，或把段数算成转向点数。** 段数 = 转向点数 + 1；首末帧只是边界；
10. **把 `direction_before` / `direction_after` 当成"又一次测量"。** 它们由 `kind` 推导（第 585–590 行）；
11. **把 peak / valley 与正向 / 负向说反。** peak = 正向 → 负向；valley = 负向 → 正向；
12. **以为转向检测用了 `ds` 的正负号。** 实际用原始 `x_px`；`ux > 0` 才使"正向 = x 增大 = ds 增大"（第 509–510 行）；
13. **把 EXP-004 的专属口径当成通用规则。** 标定常量、gate、20 px 口径都只对本实验冻结（第 20–21、30 行）；
14. **以为要"重新运行 demo"才能得到这 6 个转向点。** `demo\run_m53_plot.py` 第 15–19 行明确不重新运行转向检测，只用 M5.2 冻结的 6 个 frame（第 67–74 行）；
15. **在 L12 就提前展开周期 / 频率 / 频谱（FFT）。** 本课边界只到"检测转向点 + 切分运动段"；
16. **只看 frame 而忽略 `time_s` / `x_px` / `ds_mm` 的逐字核对。** 冻结值与真实数据行必须逐字一致（第 13.4 节）。

> L12 把 L11 的"Δds 变号 = 方向改变"落成一条可执行、可复现的规则：`detect_turning_points()`（`src\dynamic_displacement.py` 第 491–622 行）只用**原始 `x_px` 序列**（`detected=True` 且 `x_px` 非空、按 frame 升序；第 496、524–526 行），**不平滑、不滤波、不插值、不补帧、不预测**（第 497 行），同时把 `valid=False` 的行**只统计、不删除**（第 527 行）。状态机（第 541–567 行）维护 `direction`（0 / +1 / −1）、`extreme_index`（当前方向上的极值）与 `turn_indexes`（已确认转向点）：`direction == 0` 时用 `|x_i − x_extreme| ≥ 20` 确定方向；`direction == +1` 时持续更新峰值、一旦从峰值反向走满 20 px 就确认 **peak**（第 558 行）；`direction == −1` 时镜像处理、反向走满 20 px 确认 **valley**（第 565 行）。`MIN_TURN_TRAVEL_PX = 20.0`（第 87 行）的依据写在 docstring 第 503–506 行：静止段相邻帧 |dx| 中位数约 0.13 px、静止段最大约 1.25 px，远达不到 20 px，所以不会制造假转向。**转向点存的是极值帧，不是确认帧**：真实案例 peak f491 在 f505 才确认、valley f602 在 f732 才确认、peak f838 在 f971 才确认；确认滞后是抗噪与可复现的代价。`turns` 输出（`describe()` 第 569–576 行；turns 第 581–592 行）包含 `frame` / `time_s` / `x_px` / `ds_mm` / `kind` / `direction_before` / `direction_after`，其中 `direction_before` / `direction_after` 由 `kind` 推导（第 585–590 行），不是再次测量。`segments` 输出（第 594–620 行）用 `boundary_indexes = [0] + 所有转向点 + [终点]`（第 595 行）切分；每段有 start/end frame、time、x、direction、`travel_px`（第 600 行）与 `below_min_travel`（第 617 行）；**段数 = 转向点数 + 1**（第 479 行），首帧和末帧只作为边界（第 507–508 行）。**`below_min_travel` 比较的是"整个运动段两端之间的行程"，与转向确认使用的"从当前极值反向的行程"不是同一个概念**（两者都用 20 px，但比较对象不同）。EXP-004 的真实结果是：**6 个转向点**（491 peak、602 valley、838 peak、1063 valley、1254 peak、1513 valley）与 **7 个运动段**（0→491 正向 205.05 px、491→602 负向 84.80 px、602→838 正向 126.17 px、838→1063 负向 92.22 px、1063→1254 正向 190.09 px、1254→1513 负向 128.80 px、1513→1765 正向 188.61 px），与 `demo\run_m53_plot.py` 第 67–74 行冻结的 6 个 frame 完全一致。项目的工程思想是：**保留原始数据、不平滑、不插值、不补帧、不预测，用明确、冻结、可复现的规则处理噪声**（第 16、27、28、30 行）；课程关系是 **L10（ds）→ L11（Δds 与运动方向）→ L12（自动检测转向点、切分运动段）→ 后续课程（周期、频率、频谱等，本课不展开）**。
