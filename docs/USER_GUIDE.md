# VisionMotion 用户使用指南

> 面向**第一次接触 VisionMotion、不懂源码**的普通用户。
> 目标：跟着本文，从零把项目跑起来并看到结果。
>
> 想理解算法、标定、QC、数据替换等进阶内容，请看根目录 [README](../README.md) 与 `docs/` 下的报告；本文不展开。

## 1. 这是什么

VisionMotion 是一个**基于计算机视觉的低成本、非接触式位移与振动监测**项目：用普通摄像设备拍摄机械目标的运动，通过可解释的图像处理得到目标的**位置时间序列**，并据此测量振动的**周期与频率**，最后与基础物理模型做对照。

**当前主要能力（真实情况）：**

- 单张图片：检测画面中的**红色标记**，给出中心位置并画出叠加图与掩膜（M2）。
- 普通视频：逐帧检测红色标记，输出**像素坐标时间序列** CSV 与叠加视频（M3）。
- 静态 / 动态位移：在已有标定与冻结规则下把像素位置换算成**毫米位移**（M4 / M5，需要自采标定数据）。
- 外部公开视频：按冻结的视觉规则提取正式轨迹（M6.2）。
- 最终成果：周期 / 频率 / FFT 交叉验证 / 标准模型对照的可视化（M6.3，基于**仓库内已封板的轨迹 CSV**）。

**请务必分清三类内容：**

| 类别 | 含义 | 例子 |
| --- | --- | --- |
| 当前真实运行能力 | 现在用源码 / demo 真能跑出来的东西 | M2 / M3 / M5.3 / M6.3 的可运行脚本 |
| 冻结实验结果 | 已经封板、写进报告与结果的数值 | `EXP-EXT-LAB67-V1` 的周期 0.542593 s、频率 1.843003 Hz |
| 教学 / 历史实验 | 学习文档中的例子，不代表当前通用能力 | `docs/learning/` 下的 L01–L20 |

**一句话**：这是一个"跑得通、讲得清、可复现"的教学型科研项目，**不是**通用目标跟踪工具，也**不是**计量级测量系统。

## 2. 使用前准备

### 2.1 软件

- **操作系统**：Windows（本项目当前在 Windows 上验证）。
- **Python**：本项目验证环境为 **Python 3.14.1**（见 README §9）。
- **终端**：Windows PowerShell（本文命令都在 PowerShell 下执行）。
- 提示：`tests/` 用到的 pytest 属于开发依赖，普通用户**不需要**安装。

### 2.2 项目目录（普通用户只需认识这几个）

```text
VisionMotion/
├─ data/      # 你自己的原始素材（图片 / 视频）
├─ results/   # 程序输出 + 已封板的实验结果
├─ demo/      # 可以直接运行的演示脚本
├─ src/       # 程序内部模块（普通用户一般不用打开）
├─ tests/     # 自动化测试（普通用户不用管）
└─ docs/      # 报告与文档（含本指南）
```

### 2.3 数据放哪里

| 目录 | 放什么 | 是否随仓库分发 |
| --- | --- | --- |
| `data/raw/` | **自采**实验图片 / 视频（你自己的素材） | 否（需你自己准备） |
| `results/` | 程序输出，以及已封板的结果（轨迹 CSV、成果图等） | 是（部分结果随仓库提供） |
| `_external/` | **第三方公开**视频 | 否（需你自己准备） |

注意三点：

1. `_external/` **不在** `data/` 里面，它是项目根目录下的独立文件夹。
2. 请**不要**自行搬动或重命名这些目录，项目里的脚本按固定路径读取。
3. `data/processed/` 当前版本**没有作为主要运行入口使用**，普通用户不需要往里面放东西。

## 3. 安装 Python 与创建虚拟环境

在 PowerShell 中先进入项目根目录（例如 `cd "C:\Users\杨千贤\Desktop\VisionMotion"`），然后逐条执行：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**你应该看到什么：**

- `python --version` 输出 `Python 3.14.x` 之类的版本号（本项目在 3.14.1 验证）。
- 激活成功后，命令提示符前会出现 `(.venv)` 前缀，例如：
  `(.venv) PS C:\Users\杨千贤\Desktop\VisionMotion>`
- `pip install ...` 最后出现 `Successfully installed ...`，或提示依赖已满足。

**为什么用 `.venv`：** 把本项目的依赖装进一个独立环境，不污染你电脑上其它 Python 项目。

**如果 `Activate.ps1` 被阻止**（提示"禁止运行脚本"）：这是 PowerShell 执行策略限制。本项目的既有做法是把**当前用户**策略设为 `RemoteSigned`：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

不要放宽到 `Unrestricted`，也不要改计算机级策略。还原命令见 README §17。

> 依赖清单见 [`requirements.txt`](../requirements.txt)（共 5 项：opencv-python / numpy / matplotlib / Pillow / python-pptx）。普通用户不需要逐个理解，装完即可。

## 4. 第一次运行：推荐从 M6.3 开始

### 4.1 为什么第一次推荐 M6.3

- 项目的**原始视频 / 图片不随仓库分发**（体积大，或属第三方数据），所以 M2–M6.2 都需要你本地先准备好对应素材。
- 而 `results/EXP-EXT-LAB67-V1_trajectory.csv` **已经作为仓库内结果存在**。
- M6.3 只使用这个 CSV 就能生成最终成果图，**不需要任何外部视频**。

因此对"第一次拿到项目"的用户，M6.3 是最稳的入口。

### 4.2 运行命令

在项目根目录、已安装依赖的情况下执行：

```powershell
.\.venv\Scripts\python.exe demo\run_m63_final_visualization.py
```

（如果你已经激活了 `.venv`，也可以简写为 `python demo\run_m63_final_visualization.py`。）

### 4.3 它做什么（务必正确理解）

```text
已有封板 trajectory CSV
   → M6.3 可视化 / 一致性核对
   → 三张最终成果图
```

**这不是"从外部视频重新跑一遍完整算法"。** 它读取仓库里封板好的轨迹数据，重新画出成果图并做自动自检。因此：

- 没有外部视频也能运行；
- 它**不会**重新计算周期 / 频率 / FFT，而是使用封板数值；
- **它不代表**换一段新视频就会得到同样的结果。

### 4.4 输入与输出

- 输入：`results/EXP-EXT-LAB67-V1_trajectory.csv`（外部公开教育视频的封板轨迹，160 行）。
- 输出（都在 `results/` 下）：

| 图 | 文件 | 内容 |
| --- | --- | --- |
| 图 A | `results/EXP-EXT-LAB67-V1_fig_A_y0_timeseries.png` | 我到底测到了什么（160 个采样点、局部极值） |
| 图 B | `results/EXP-EXT-LAB67-V1_fig_B_frequency_comparison.png` | 测量值 / 标准模型 / FFT 的对照 |
| 图 C | `results/EXP-EXT-LAB67-V1_fig_C_pipeline.png` | 完整技术流程 |

### 4.5 怎么判断成功

**你应该看到**终端打印出三张图的路径与尺寸信息，并在末尾看到：

```text
自检结论：全部通过
```

同时在 `results/` 目录里看到上面三个 PNG 被（重新）生成。若结论是"存在未通过项"，或中途出现错误信息，请看第 8 节常见问题。

## 5. 我有自己的图片：运行 M2

M2 用一张**包含红色标记**的图片，检测红色目标并给出中心位置。

1. **放图片**：把你的图片放进 `data/raw/`（放进别的目录也可以，用路径指定即可）。
2. **运行（推荐：直接指定输入图片，不用改源码）**：

   ```powershell
   .\.venv\Scripts\python.exe demo\run_single_image_detection.py `
     --input data\raw\my_image.jpg `
     --out-dir results\my_image
   ```

   - `--input` 是输入图片，`--out-dir` 是输出目录（目录不存在会自动创建）；
   - **不需要打开源码修改 `IMAGE_PATH`**；
   - 输出文件名**自动按输入图片的文件名派生**（`my_image.jpg` → `my_image_overlay.png` /
     `my_image_mask.png`），不会再借用 `EXP-001-IMAGE-001` 这个名字；
   - 去掉 `--out-dir`，输出就写到默认的 `results\`；
   - 如果目标文件已经存在，程序**默认停止**而不是覆盖；确认要覆盖时再加 `--overwrite`
     （它**只控制输出文件是否覆盖**，与检测参数 / 检测逻辑无关）。
3. **相对路径**：`--input` / `--out-dir` 的相对路径按**项目根目录**解析，
   不是按你当前所在的目录；写绝对路径则原样使用。
4. **结果**（下面以第 2 步的命令为例）：
   - `results\my_image\my_image_overlay.png`：**叠加图** —— 原图上画出红色目标的方框、中心点与坐标。
   - `results\my_image\my_image_mask.png`：**掩膜图** —— 只保留"被判为红色"的白色区域，用来直观检查检测是否合理。
5. **更早版本的无参数运行方式仍然兼容**：

   ```powershell
   .\.venv\Scripts\python.exe demo\run_single_image_detection.py
   ```

   它固定使用 `data/raw/EXP-001-IMAGE-001.jpg`，输出 `results/EXP-001-IMAGE-001_overlay.png` 与
   `results/EXP-001-IMAGE-001_mask.png`。但请注意：
   **这是为兼容旧教程保留的默认行为，不是推荐用来处理自己图片的方式**，
   而且它**没有**覆盖保护——它会写回旧的 EXP-001 结果。

**你应该看到**终端打印图片尺寸、检测到的中心坐标、面积、外接矩形，最后打印两个结果图片的保存路径。

> 说明：M2 检测的是**红色**标记。若图片里没有红色目标，脚本会提示"检测失败：未检测到红色目标"，并只保存掩膜图。此时**流程确实已经完成（不是崩溃）**，但退出码还会进一步区分"至少检测到一次"与"全程零检出"。

**退出码（M2）**：

| 退出码 | 含义 |
| --- | --- |
| `0` | 图片处理完成，并且检测到目标 |
| `1` | 输入图片不存在 / 无法读取 / 结果写入失败 |
| `2` | 目标输出已存在且未加 `--overwrite`；另外 argparse 参数用法错误默认也是 `2` |
| `3` | 图片处理完成，但**没有检测到目标**（流程正常，只是没找到红色标记） |

- 终端输出负责**给你看细节**（检测结果、中心坐标、保存路径）；退出码负责**给脚本与自动化判断**。
- `3` **不是崩溃**：程序正常跑完了，只是没有任何目标被检出。

## 6. 我有自己的普通视频：运行 M3

M3 用一段**包含红色目标**的视频，逐帧检测红色标记，输出**像素坐标时间序列**。

1. **放视频**：把你的视频放进 `data/raw/`（放进别的目录也可以，用路径指定即可）。
2. **运行（推荐：直接指定输入视频，不用改源码）**：

   ```powershell
   .\.venv\Scripts\python.exe demo\run_video_tracking.py `
     --input data\raw\my_video.mp4 `
     --out-dir results\my_video
   ```

   - `--input` 是输入视频，`--out-dir` 是输出目录（目录不存在会自动创建）；
   - **不需要打开源码修改输入路径**；
   - 输出文件名**自动按输入视频的文件名派生**（`my_video.mp4` → `my_video_track.csv` /
     `my_video_overlay.mp4`），不会再借用 `EXP-002-VIDEO-001` 这个名字；
   - 去掉 `--out-dir`，输出就写到默认的 `results\`；
   - 如果目标文件已经存在，程序**默认停止**而不是覆盖；确认要覆盖时再加 `--overwrite`
     （它**只控制输出文件是否覆盖**，与检测 / 标定 / QC / SHA 无关）。
3. **相对路径**：`--input` / `--out-dir` 的相对路径按**项目根目录**解析，
   不是按你当前所在的目录；写绝对路径则原样使用。
4. **结果**（下面以第 2 步的命令为例）：
   - `results\my_video\my_video_track.csv`：逐帧的**像素坐标时间序列**。
   - `results\my_video\my_video_overlay.mp4`：叠加视频（在每帧上画出检测到的目标），用于人工核对。
5. **更早版本的无参数运行方式仍然兼容**：

   ```powershell
   .\.venv\Scripts\python.exe demo\run_video_tracking.py
   ```

   它固定使用 `data/raw/EXP-002-VIDEO-001.mp4`，输出 `results/EXP-002-VIDEO-001_track.csv` 与
   `results/EXP-002-VIDEO-001_overlay.mp4`，行为与以前完全一致。但请注意：
   **这是为兼容旧教程保留的默认行为，不是推荐用来处理自己视频的方式**，
   而且它**没有**覆盖保护——它会写回旧的 EXP-002 结果。
6. **如果叠加视频失败**：若图形编码器不可用，程序**不会中断**，而是**回退**保存最多 5 张代表性 PNG，文件名形如
   `results/my_video_overlay_frame0000_start.png`（默认运行时则是 `results/EXP-002-VIDEO-001_overlay_frame0000_start.png`；标签可能是 `start` / `middle` / `end` / `fastest_motion` / `blurriest`）。
   只要 `_track.csv` 正常生成、终端提示已回退保存 PNG，这次追踪就算**成功完成**（回退只影响可视化，不影响 CSV）。
   注意：这里的"成功完成"指**程序跑完了整条处理流程**；目标到底有没有被检出，要看终端统计与 CSV 里的 `detected` 列，以及下面的退出码。

**你应该看到**终端打印：CSV 文件路径、CSV 行数、叠加视频路径（或"叠加视频是否成功：否（…已回退保存 N 张代表性 PNG）"）、CSV 数据完整性自检结果，以及一行**轨迹完整性**。

> 关于帧数：正常完整运行时，CSV 行数**通常**应与视频文件声明的帧数一致；终端会同时显示"总帧数（文件声明）"与"实际处理帧数"，两者不一致时请留意下面的轨迹完整性结论。程序还会额外做一次**末帧可读性检查**，用来辅助判断这条轨迹是否覆盖到视频结尾。

> **重要**：M3 得到的是**像素坐标**（`x_px` / `y_px`），**不是**毫米位移。要把像素换算成毫米需要标定，属于 M4 / M5 的高级流程。

**退出码（M3）**：

| 退出码 | 含义 |
| --- | --- |
| `0` | 轨迹完整（`complete`）、至少检出过一次目标、且 CSV 自检通过 |
| `1` | 输入 / 视频处理错误，或 CSV 自检未通过 |
| `2` | 目标输出已存在且未加 `--overwrite`；另外 argparse 参数用法错误默认也是 `2` |
| `3` | 轨迹完整（`complete`）、CSV 自检通过，但**全程没有检出到任何目标** |
| `4` | 用户主动按 `Ctrl+C` 中断逐帧视频处理 |
| `5` | 轨迹完整性**存疑或未验证**（终端会显示 `suspect` 或 `unverified`） |

- 同样：终端输出（检出帧数、检出成功率、最长连续丢失帧、CSV 自检明细）负责给你看细节，退出码负责给脚本判断。
- **部分漏检不会变成失败**：170 帧里检出 80 帧，退出码仍然是 `0`；只有**全程 0 检出**才是 `3`。
- 退出码 `5` **不是**崩溃，**不是**输入文件不存在，**不是** CSV 自检失败，也**不是**你按了 Ctrl+C。它只是说：程序完成了本次流程，但**没有足够证据把输出当作"已确认完整的视频轨迹"**——请人工确认后再使用这次结果。

> **提前停止**：M3 运行过程中可以按 `Ctrl+C` 主动终止逐帧处理。程序会尽量保留已经处理的数据并正常收尾，退出码为 `4`。此时生成的 CSV / overlay **通常只覆盖截至中断时的部分视频**，不应直接视为完整视频轨迹。
> `4` 不是崩溃，也不是错误——它只是说明"这次是你主动停下来的"。

## 7. 输出文件怎么看

### 7.1 图片（PNG）

- **overlay（叠加图）**：在原图上标出检测结果（方框、中心、坐标），用来快速判断"检测到的东西对不对"。
- **mask（掩膜图）**：把满足条件的像素涂成白色、其余为黑，用来判断"阈值 / 分割是否合理"。
- **最终成果图（fig_A / fig_B / fig_C）**：M6.3 的三张成果图，分别回答"测到了什么""与模型 / FFT 的对照如何""流程是怎样的"。

### 7.2 轨迹 CSV 是什么

M3 的 `_track.csv` 每行对应视频中的一帧，各列含义（初学者版）：

| 列 | 含义 |
| --- | --- |
| `frame` | 第几帧（从 0 开始） |
| `time_s` | 该帧的时间，单位秒（= 帧号 ÷ 帧率） |
| `x_px` | 目标中心在画面中的横向像素坐标（左右方向） |
| `y_px` | 目标中心在画面中的纵向像素坐标（上下方向，向下为正） |
| `area_px` | 目标区域的像素面积（大致反映目标大小） |
| `detected` | 这一帧是否检测成功（`True` / `False`） |

一句话：**这是一个"目标什么时候在哪里"的表格**。用 Excel 就能打开查看；横轴取 `time_s`、纵轴取 `x_px`（或 `y_px`）画曲线，就能看出目标的运动。

| 问题 | 简要说明 |
| --- | --- |
| 文件不存在（"原始图片 / 视频不存在"） | **M2 / M3 例外**：它们支持 `--input`，提示分别为 "错误：输入图片不存在：<绝对路径>" 与 "错误：输入视频不存在：<绝对路径>"，直接用参数指定你的文件即可。其余脚本用的是**写死的固定文件名**；请把素材放对目录（`data/raw/` 或 `_external/...`），并改成脚本期望的名字。 |
| PowerShell 激活失败 | 用 `.\.venv\Scripts\Activate.ps1`（带 `.\`）；被阻止时按第 3 节把**当前用户**策略设为 `RemoteSigned`。 |
| 中文字体缺失 | `run_m53_plot.py` 固定用 `C:\Windows\Fonts\msyh.ttc`；M6.3 会自动挑选可用中文字体。缺字体就装上微软雅黑即可。 |
| OpenCV 窗口打不开 | 只有 `demo/pick_calibration_points.py` 需要弹窗（M4 标定）；无图形界面时该步无法完成。M2 / M3 / M6.3 不需要窗口。 |
| SHA-256 不匹配 | 说明你手上的文件不是该阶段的冻结版本；请核对文件来源与哈希，**不要删代码里的校验来"绕过"**。 |
| MP4 编码器失败 | M3 会自动回退保存代表性 PNG；只要 `_track.csv` 正常生成，即算成功。 |

## 9. 普通用户的能力边界（重要）

### 你现在可以安全做的事情

- 运行 **M6.3**（查看最终成果图）；
- 运行 **M2 / M3**（检测图片、跟踪视频中的红色目标）；
- 用 Excel 或任意工具**查看 CSV**、用图片查看器**查看 PNG**。

### 请不要做的事情

1. **不要随便改"冻结"参数**：源码里的标定常量、有效门限（valid gate）等是实验封板值，改动会让结果无法追溯。
2. **不要把外部视频当成已标定的毫米数据**：M6.2 / M6.3 用的是**像素位置 y₀**；本项目当前**未**为这段外部视频建立有效的 px/mm 标定。
3. **不要把 M6.3 的周期 / 频率当成"每次运行重新算出来"**：那是**封板数值**，M6.3 只做可视化与一致性核对。
4. **不要删除 SHA-256 校验来"解决错误"**：校验失败说明输入不是对应版本，删掉只会让结果失真。
5. **不要以为换一段新视频就会自动得到同样的周期 / 频率**：换视频需要重新采集、重新标定、重新评估，不能照搬旧结果。

### 关于上游轨迹完整性（M4 / M5）

M4 / M5 会先让 M3 生成 `_track.csv`，再据此计算位移。如果上游轨迹的完整性没有被确认：

- 完整性为 **`suspect`（存疑）或 `unverified`（未验证）**时，M4 / M5 **会继续计算位移**，但会在终端显示**明确警告**，提醒你使用结果前人工核对上游轨迹；
- 完整性为 **`not_evaluated`（未评估，通常来自你按了 Ctrl+C）**时，M4 / M5 会**跳过该视频的位移计算，不生成 `_ds.csv`**——避免把一段没跑完的轨迹直接当成正式位移结果。

M4 / M5 也会给出**机器可读退出码**（用法与 M2 / M3 一致）：

| 退出码 | 含义 |
| --- | --- |
| `0` | 本次要跑的实验都成功完成，且预期生成的 `_ds.csv` 都已落盘 |
| `1` | 存在阻断性失败：输入视频不存在 / 视频无法处理 / 冻结常量自检未通过 / 上游完整性 `not_evaluated` 导致跳过 / 预期生成的 `_ds.csv` 未落盘 |

- M4 一次会跑三个视频，**只要有一个失败，整体退出码就是 `1`**（不会因为其它的成功就变回 `0`）；
- 按冻结规则"有效帧不足因此不写 `_ds.csv`"是**正常结果**（不是失败），例如 `EXP-003-STATIC-001` 本来就没有 `_ds.csv`；而 `not_evaluated`（你按了 Ctrl+C）导致的跳过**算失败**，退出码为 `1`；
- 在 PowerShell 里查看退出码：

  ```powershell
  .\.venv\Scripts\python.exe demo\run_m43_displacement.py
  $LASTEXITCODE
  ```

**注意：M4 / M5 默认会重新写入 `results/` 里的结果文件。** 它们的输出目录固定是 `results/`（和仓库里已冻结的结果放在一起）：

- 目标文件**不存在**时，正常执行，不会有任何提示；
- 目标文件**已存在**时，程序会在写盘之前打印一行 `[警告] 输出文件已存在，将重新写入冻结结果：<路径>`，然后**继续运行**（不会拒绝覆盖、也不会停下来问你）。

这些被重新写入的文件里，`_track.csv` / `_ds.csv` 是**已经被 Git 跟踪的冻结结果**（`_overlay.mp4` 被忽略）。当前冻结结果的重算是确定性的、并且有关键结果 SHA-256 校验，但**如果你本地有不想被覆盖的产物**，请在运行前先看一下工作区状态：

```powershell
git status --short
```

确认没有需要保留的改动后再运行。
