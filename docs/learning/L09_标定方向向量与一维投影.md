## 3. compute_scale()：从"两点 + 真实长度"到像素尺度（第 100～144 行）

L08 只要求"认识 `compute_scale()` 的作用"；L09 要把它逐行读完。

### 3.1 函数签名与 docstring（第 100～117 行）

```python
# src\calibration.py 第 100 行
def compute_scale(point1, point2, real_distance_mm):
```

docstring（第 101～117 行）写清了全部契约：

- 参数 `point1`：P1（10 cm 刻线）的像素坐标，例如 `(1043.8, 559.3)`；
- 参数 `point2`：P2（16 cm 刻线）的像素坐标，例如 `(1403.0, 559.3)`；
- 参数 `real_distance_mm`：P1 到 P2 的真实距离，单位毫米（本阶段固定 60.0）；
- 返回字典三个键：`pixel_distance`（`L_pixel`）、`px_per_mm`（`k = L_pixel / real_distance_mm`）、`mm_per_px`（`1 / k = real_distance_mm / L_pixel`）；
- 报错约定：参数不是数字 / 点不是两个数字 → `TypeError`；点长度不对 / 两点重合 / `real_distance_mm <= 0` → `ValueError`。

> **材料分类提醒**：docstring 里的坐标 `(1043.8, 559.3)`、`(1403.0, 559.3)` 是**教学示例**（写文档时的示意值），
> 不是项目的冻结标定点；项目真正使用的 M4 标定点是 `(1036.23, 490.58)` 与 `(1381.64, 488.20)`
> （`src\displacement.py` 第 48～50 行，见第 7 节）。

### 3.2 参数检查（第 118～120 行）

```python
# src\calibration.py 第 118～120 行（原文）

```

- `_check_point()`（第 46～70 行）负责：必须是长度为 2 的序列、两个元素都能转成数字、都是有限数值（不能是 `nan` / `inf`）；字符串、布尔值都会被拒绝；
- `_to_float()`（第 32～43 行）负责把 `real_distance_mm` 转成 `float`，转不了时抛 `TypeError`；
- 这一步的产物是三个干净的 `float`：`x1, y1, x2, y2` 与 `real_distance_mm`。

### 3.3 real_distance_mm 合法性检查（第 122～126 行）

```python
# src\calibration.py 第 122～126 行（原文）

        raise ValueError("real_distance_mm 必须是有限数值（不能是 nan 或 inf）")

```

- 为什么必须有这一关：尺度是"像素数 ÷ 毫米数"；除数为 0 或负数时，`px_per_mm` 要么无定义，要么符号失去物理意义；
- 注意错误信息里带上了当前值（`%g`），这是一条实用的工程习惯：报错要能直接指出"错在哪个值上"。

### 3.4 dx、dy、pixel_distance（第 128～131 行）

```python
# src\calibration.py 第 128～131 行（原文）
    # L_pixel = sqrt((x2 - x1)^2 + (y2 - y1)^2)
    dx = x2 - x1
    dy = y2 - y1
    pixel_distance = math.hypot(dx, dy)
```

- `dx` / `dy` 是"两个点的差值"，也就是**原始方向向量** `v = P2 - P1` 的两个分量（第 5 节会继续用它算方向）；
- `math.hypot(dx, dy)` 等价于 `sqrt(dx² + dy²)`，但由标准库实现得更稳（避免中间结果溢出）；
- 得到的 `pixel_distance` 就是 **`L_pixel`**，单位是像素，是两点之间的直线距离（欧氏距离）。

### 3.5 两点重合检查（第 134～135 行）

```python
# src\calibration.py 第 134～135 行（原文）
    # 两点重合就没有长度，尺度无从谈起
    if pixel_distance == 0:
        raise ValueError("P1 和 P2 不能重合（像素距离为 0），无法计算像素尺度")
```

- 两点重合时 `L_pixel = 0`，`px_per_mm` 会变成 0、`mm_per_px` 会除以 0——两种结果都没有意义；
- 这个检查与第 170～171 行（`unit_direction()` 的零长度检查）是同一个原则：**零长度向量没有方向，也没有尺度**。

### 3.6 px_per_mm、mm_per_px（第 137～138 行）

```python
# src\calibration.py 第 137～138 行（原文）

    mm_per_px = real_distance_mm / pixel_distance
```

两个量互为倒数：

```text

mm_per_px = L_real_mm / L_pixel     （每个像素 = 多少毫米现实长度）

```

项目里把 `px_per_mm` 当作**主表达方式**（`src\displacement.py` 第 52 行注释原文："像素/毫米，本阶段位移换算的主表达方式"），

## 4. 三个量与四个单位：L_pixel、px/mm、mm/px

第 3.6 节已经给出公式，这里把三者的关系与读法整理成一张表：

| 量 | 公式（源码行） | 单位 | 直观解释 |
| --- | --- | --- | --- |
| `L_pixel`（`pixel_distance`） | `hypot(dx, dy)`（第 128～131 行） | px | 两个像素点之间的直线距离 |
| `px_per_mm = k` | `L_pixel / L_real_mm`（第 137 行） | px/mm | 每 1 mm 现实长度占多少像素 |
| `mm_per_px = 1/k` | `L_real_mm / L_pixel`（第 138 行） | mm/px | 每个像素代表多少毫米现实长度 |

三个等价关系（可在自测时互相推导）：

```text
px_per_mm × mm_per_px = 1
L_pixel = px_per_mm × L_real_mm
L_real_mm = L_pixel × mm_per_px
```

量纲检查法（防止乘除写反）：

```text
px ÷ mm = px/mm      ✓（像素数除以毫米数）
mm ÷ px = mm/px      ✓（毫米数除以像素数）
px × px/mm = px      ✓（L_pixel 由 L_real_mm 乘 px/mm 得到时，毫米被约掉）
```

项目自检里也检查"互为倒数"：
`src\displacement.py` 第 142～147 行检查 `PX_PER_MM × MM_PER_PX ≈ 1`（容差 `1e-4`）；
`src\dynamic_displacement.py` 第 159～165 行检查 `MM_PER_PX_004` 与 `1 / PX_PER_MM_004` 一致（容差 `1e-6`）。

**易错提醒**：`ds_mm = ds_px / PX_PER_MM`（除以 px/mm），等价于 `ds_px × MM_PER_PX`；
若把除法写成乘法（`ds_px × PX_PER_MM`），结果会变成正确值的约 33.14 倍（`5.756961²`），
而不是差一点点——这是 L08 记录过的头号易错点，在 L09 的复算里同样适用。

## 5. unit_direction()：原始方向向量 → 单位方向向量（第 147～173 行）

### 5.1 函数签名与 docstring（第 147～161 行）

```python
# src\calibration.py 第 147 行
def unit_direction(point1, point2):
```

docstring 里的关键约定（第 149～161 行）：

- 方向约定：**从 P1（10 cm）指向 P2（16 cm）**（第 149 行）；
- 定义式：`u = (P2 - P1) / |P2 - P1|`，"所以一定满足 `ux² + uy² = 1`"（第 151 行）；
- 返回：`{"ux": ..., "uy": ...}`（第 157～159 行）；
- 坐标约定提醒：图像坐标系里 **y 向下为正**，所以尺子若"向右下倾斜"，`uy` 为正（第 159 行）。

### 5.2 原始方向向量 v = (dx, dy)（第 166～167 行）

```python
# src\calibration.py 第 166～167 行（原文）
    dx = x2 - x1
    dy = y2 - y1
```

`v = (dx, dy) = P2 - P1` 就是**原始方向向量**。它同时携带两种信息：

- 方向：从 P1 指向 P2；
- 长度：`|v| = L_pixel`——与 `compute_scale()` 里算的是同一个量（两处都用 `hypot`）。

用 M4 的冻结标定点做减法：`v = (1381.64 - 1036.23, 488.20 - 490.58) = (345.41, -2.38)`。

### 5.3 length（第 168 行）

```python
# src\calibration.py 第 168 行（原文）
    length = math.hypot(dx, dy)
```

`length` 就是 `|v|`。注意：此时 `length` 还不是 `unit_direction()` 的返回值，
它只是"接下来做除法用的分母"。

### 5.4 零长度检查（第 170～171 行）

```python
# src\calibration.py 第 170～171 行（原文）
    if length == 0:
        raise ValueError("P1 和 P2 不能重合（长度为 0），无法计算方向向量")
```

零向量没有方向：向量只有长度为零时方向才不确定，所以这里必须显式报错，而不是返回 `(0, 0)` 或 `nan`。

### 5.5 单位方向向量与它的性质（第 173 行）

```python
# src\calibration.py 第 173 行（原文）
    return {"ux": dx / length, "uy": dy / length}
```

性质（对任意非零 `v` 都成立，在浮点精度内）：

```text
u = v / |v| = (dx/|v|, dy/|v|)
|u| = sqrt(ux² + uy²) = 1
```

用 M4 冻结标定点复算：`u ≈ (0.999976262, -0.006890199)`；
冻结常量是 `U = (0.999976, -0.006894)`，两者差 `ux: 2.6e-7`、`uy: 3.8e-6`，
远小于自检容差 `1e-4`（`src\displacement.py` 第 128～135 行专门检查"u 与冻结标定点一致"）。
差的来源是数值只保留有限位小数（打印/冻结精度），不是算法差异；第 8 节的真实数据验证会说明
**CSV 里实际用到的方向是 `U` 归一化之后的方向**。

### 5.6 为什么必须归一化

三条理由，从"代码正确"到"物理意义"逐层递进：

1. **单位一致性（量纲）**：`s = x·ux + y·uy` 里 `x`、`y` 的单位是像素；
   只有 `|u| = 1` 时，`s` 的单位才是"px × 1 = px"。若 `|u| = 2`，同样一个点会得到 2 倍大的 `s`，
   这个数就不再是"沿方向的像素距离"。
2. **表示的唯一性**：同一条方向可以写成 `(1, 0)`、`(2, 0)`、`(100, 0)`……如果不归一化，
   同一个方向会给出不同的 `s`；归一化让"方向"这种信息只保留方向本身，丢弃"向量有多长"。
3. **几何可读性**：只有 `|u| = 1` 时，`s = |v|·cos θ`（`θ` 是点向量与 `u` 的夹角）这条几何解释才成立，
   `ux` / `uy` 也才能直接读作"与坐标轴夹角的余弦 / 正弦"。

**教学示例（非项目数据）**：设方向写成 `u_raw = (2, 0)`，点 `(10, 0)`：

- 不归一化：`s = 10×2 + 0×0 = 20`；
- 归一化后：`u = (1, 0)`，`s = 10×1 + 0×0 = 10`。

点在 x 轴上离原点 10 px，所以"沿方向走了多远"的正确答案是 10——**归一化让 s 说人话**。

项目里的纪律与此一致：未归一化的"原始方向向量"只作为中间量存在，
从未直接进入 `s` 的计算——`project_point()` 第 196～202 行从结构上保证这一点（第 6.5 节）。

### 5.7 ux、uy 的几何意义

把单位向量写成 `u = (cos θ, sin θ)`（`θ` 是 `u` 与图像 x 轴正方向——也就是"向右"——的夹角，
按图像坐标系"y 向下"来量）：

- `ux`：`u` 在水平方向上的分量，`ux > 0` 表示整体指向右侧；
- `uy`：`u` 在竖直方向上的分量，`uy > 0` 表示整体指向"下方"（画面下方），`uy < 0` 表示指向"上方"；
- `|ux|` 接近 1、`|uy|` 接近 0：方向几乎水平；
- 符号约定决定方向的正负头尾：交换 `P1` 与 `P2`（或把 `u` 取反）会得到 `(-ux, -uy)`，
  投影坐标的"增大方向"随之反转——所以方向约定必须写死在文档与源码注释里（第 149 行）。

两组真实常数的几何解读：

| 常量（源码行） | 值 | u 的模 | 与 +x 轴夹角 | 几何解读 |
| --- | --- | --- | --- | --- |
| M4 `U`（`src\displacement.py` 第 55 行） | `(0.999976, -0.006894)` | `0.999999763906` | `atan2(-0.006894, 0.999976) ≈ -0.006894 rad ≈ -0.395°` | 几乎水平向右，略向上（图像里 y 变小） |
| M5 `U_004`（`src\dynamic_displacement.py` 第 66 行） | `(0.999992, -0.003913)` | `0.999999655816` | `≈ -0.003913 rad ≈ -0.224°` | 几乎水平向右，略向上，比 M4 更接近水平 |

两个 `|u|` 都只差最后几个 1e-7 才等于 1——因为常量只保留 6 位小数。
这正是第 6.5 节"`project_point()` 必须再次归一化"的现实原因。

## 6. project_point()：二维坐标 → 一维 s_px（第 176～204 行）

### 6.1 函数签名与公式（第 176～191 行）

```python
# src\calibration.py 第 176 行

```

docstring（第 177～191 行）的要点：

- 功能：把一个点投影到 `direction` 方向上，返回一维投影坐标（一个浮点数）（第 178 行）；
- **投影公式**：`s = x * ux + y * uy`（第 180 行）；
- 参数：`point` 是像素坐标 `(x, y)`；`direction` 可以是 `unit_direction()` 返回的字典，
  也可以是 `(ux, uy)` 这样的长度 2 序列（第 182～185 行）；
- 归一化说明（第 187～189 行原文）："如果传入的 `direction` 不是单位向量（长度不是 1），

- 报错约定：方向向量长度为 0 时报 `ValueError`（第 191 行）。

### 6.2 读取 point 与 direction（第 193～194 行）

### 6.3 方向零长度检查与再次归一化（第 196～202 行）

```python
# src\calibration.py 第 196～202 行（原文）
    length = math.hypot(ux, uy)
    if length == 0:
        raise ValueError("direction 的长度不能为 0（必须是一个方向向量）")

    # 归一化，让 s 的单位和 point 一样是像素

    uy = uy / length
```

三个细节：

1. 这里的 `length` 是**方向向量**的模 `|direction|`，不是 `L_pixel`（同名，含义不同，读代码时要看清作用对象）；
2. 零长度检查在归一化**之前**——否则会先发生除以 0；
3. 归一化只改函数内部的局部变量 `ux` / `uy`，不会改动调用方传入的对象（元组本身也不可改写）。

### 6.4 点积与第 204 行实现

```python
# src\calibration.py 第 204 行（原文）
    return x * ux + y * uy
```

**点积（dot product）**的二维定义：

```text
a · b = ax · bx + ay · by = |a| · |b| · cos θ     （θ 是 a、b 的夹角）
```

把"点向量" `v = (x, y)` 与单位方向 `u` 代入：

```text
s = v · u = x·ux + y·uy = |v| · cos θ = v 在 u 方向上的有号投影长度
```

要点：

- 代码里就是"两乘一加"，标准库就够，不需要 numpy（第 24 行只有 `import math`）；
- 当 `|u| = 1` 时，点积的几何解释就是"投影长度"；`s` 的符号表示投影落在 `u` 正方向一侧（正）还是反方向一侧（负）；
- 点积满足交换律 `v·u = u·v`，写法上习惯把"点的坐标"放在点积左边、方向放在右边；
- 第 180 行的 docstring 公式与第 204 行的实现是**同一个式子**——注释与代码一致，是这份源码可以逐行教学的原因之一。

### 6.5 为什么 project_point() 要再次归一化方向

这是本课第 14 个重点，答案是两层：

**第一层：函数不为调用方做假设（契约式设计）。**
docstring 第 188～189 行承诺"不是单位向量就归一化"，第 196～202 行把承诺落实。
无论调用方传进来的是 `unit_direction()` 的返回值、手写的元组，还是从别处复制的常量，
函数都保证输出是"真正的沿方向像素坐标"。项目纪律也要求投影只有一个来源：

- `src\displacement.py` 第 19～20 行："不复制检测算法……不重新实现投影公式（投影唯一来源：`src.calibration.project_point`）"；
- `src\dynamic_displacement.py` 第 26 行写明"不重新实现投影公式"，第 40 行只 `from src.calibration import project_point`。

**第二层：项目里的冻结方向常量本来就不是精确的单位向量。**

| 常量 | 值 | u 的模 | 与 1 的差 |
| --- | --- | --- | --- |
| M4 `U` | `(0.999976, -0.006894)` | `0.999999763906` | `-2.361e-7` |
| M5 `U_004` | `(0.999992, -0.003913)` | `0.999999655816` | `-3.442e-7` |

原因：常量只保留 6 位小数（写进源码时被打印精度截断）。两个模块的自检也只能在**容差**内判定
"u 是单位向量"：M4 容差 `1e-4`（`src\displacement.py` 第 136～141 行），M5 容差 `1e-6`
（`src\dynamic_displacement.py` 第 139～144 行）。

`project_point()` 的再次归一化把这层截断误差"抹掉"：第 201～202 行把 `U` 换成 `U / |U|` 之后再做点积。
影响有多大？第 8 节的真实数据复核给出定量答案：

- 跳过归一化（直接用 `s = x·U`）：与 CSV 里 `s_px` 的最大差为 `8.299e-4 px`（M4）/ `9.235e-4 px`（M5）；
- 算上归一化（`s = (x·U) / |U|`）：最大差降到 `4.974e-4 px` / `4.998e-4 px`，正好等于"`s_px` 写 3 位小数"的舍入上界 `5e-4`。

还有一个更直观的对照（用冻结标定点，只读复算）：用 `project_point()` 的口径计算
`s(P2) - s(P1)`：

| 量 | M4 | M5 |
| --- | --- | --- |
| `s(P2) - s(P1)`（含再次归一化） | `345.418199 px` | `608.634653 px` |
| `L_pixel = hypot(dx, dy)` | `345.418199 px` | `608.634653 px` |
| 差 | `≈ -2.5e-9 px` | `≈ -2.1e-9 px` |

归一化之后，"沿方向的投影长度"与"两点直线距离"精确一致（浮点精度内）——
这正是几何上应有的结果（`u` 与 `P2 - P1` 平行时，投影长度就是全长）。
若不归一化，M5 的投影长度会变成 `608.634444 px`（L08 第 12.3 节记录过这个数），
比 `L_pixel` 少 `2.09e-4 px`——量级虽小，但它证明"再次归一化"不是装饰，而是真实生效的步骤。

### 6.6 为什么投影能保留沿运动方向的分量、削弱垂直方向分量

这是本课第 13 个重点。用正交分解可以一行说清：

```text
任意向量 v 都可以分解为：
    v = (v·u)·u + (v - (v·u)·u)
          └── 平行分量 ──┘   └──── 垂直分量 ────┘
其中第二项与 u 垂直。
s = v·u：只取第一个系数 (v·u)，
    垂直分量与 u 点积恒等于 0，所以对 s 没有任何贡献。
```

两条推论（都可当场验算）：

- 点沿 `u` 移动 `d` px：`Δs = d`（1:1 保留，这是"我们想测的运动"）；
- 点沿垂直于 `u` 的方向移动 `d` px：`Δs = 0`（垂直运动在 `s` 里不出现）。

**教学示例（非项目数据，用 M4 的真实方向常量做算术）**：
设 `u = (0.999976, -0.006894)`，它的垂直方向取 `n = (0.006894, 0.999976)`：

- 沿 `n` 移动 10 px：`Δs = 10 × (0.006894×0.999976 + 0.999976×(-0.006894)) = 0`（在浮点精度内恰好为 0）；
- 沿 x 轴移动 10 px：`Δs = 10 × 0.999976 = 9.99976 px`；
- 沿 y 轴（竖直）移动 10 px：`Δs = 10 × (-0.006894) = -0.068940 px`——竖直方向只"漏"进来不到 0.07 px。

所以投影的取舍是：

- **保留**沿尺（运动）方向的分量——物体沿尺移动多少，`s` 就变多少；
- **削弱**垂直方向：垂直方向的真实位移、抖动、噪声，在一维 `s` 里几乎不出现
  （准确说：垂直分量对 `s` 的贡献为 0；余下的小量来自方向常量本身"不是完全水平"）。

**概念伪代码（不是 VisionMotion 真实源码）**——对比"投影"和"直接取 x 坐标"：

```text
# 概念伪代码（不是 VisionMotion 真实源码）
若方向完全水平（u = (1, 0)）：
    s = x                     # 竖直抖动完全不进入 s
若方向是真实常量（略微倾斜）：
    s = x·ux + y·uy           # 竖直分量只按 uy 这样的小系数进入 s
```

注意："削弱"不等于"消失于系统"：如果物体真的在垂直方向有运动，`s` 是**看不到**它的——
这是"把二维压成一维"的代价；本项目的测量目标（沿尺方向的位移）正好适合这个取舍。

### 6.7 s_px 是"坐标"不是"位移"：与 L10 的接口

- `s_px` 的单位是像素（>= 0 的大数，不是"从起点走出来的距离"）；
- `s_px` 是**位置坐标**：它的零点由图像原点 `(0, 0)` 与方向 `u` 共同决定；
  换一个方向常量或换一段视频，`s_px` 的绝对值就会整体平移/改变，不能跨实验直接比较；
- 同一个点在两次不同实验里可以有完全不同的 `s_px`，但**两次之间的差**（沿方向的有号距离）才是有物理含义的"位移"；
- "相对哪个基线、怎么选基线"就是 L10 的 `s0`（本课只登记名称：`compute_s0()` 在 `src\displacement.py` 第 317 行起，规则与窗口留到 L10 展开）；
- 同理，`ds_px = s_px - s0`、`ds_mm = ds_px / PX_PER_MM` 的完整流程也留到 L10——本课只需能说清
  "`s_px` 是这条链里由投影产生的一维坐标"。

## 12. 本节课最重要的概念

1. **`compute_scale()` 的六个步骤**：参数检查（第 118～120 行）→ 真实距离合法性（第 122～126 行）→ `dx` / `dy` / `L_pixel`（第 128～131 行）→ 两点重合检查（第 134～135 行）→ `px_per_mm` / `mm_per_px`（第 137～138 行）→ 返回字典（第 140～144 行）；
2. **`L_pixel = sqrt(dx² + dy²)`**：两点之间的欧氏像素距离（第 128～131 行）；
3. **`px_per_mm = L_pixel / L_real_mm`、`mm_per_px = L_real_mm / L_pixel`**：互为倒数；量纲检查可以防乘除写反（第 137～138 行）；
4. **原始方向向量 `v = P2 - P1`**：同时携带方向与长度，长度就是 `L_pixel`（`unit_direction()` 第 166～168 行）；
5. **单位方向向量 `u = v / |v|`**：`|u| = 1`，只保留方向（第 173 行）；
6. **为什么必须归一化**：单位一致（s 的单位是 px）、表示唯一（同方向只有一种写法）、几何可读（`ux`/`uy` 才是 cos/sin）；教学反例见第 5.6 节；
7. **`ux`、`uy` 的几何意义**：`u = (cos θ, sin θ)`；图像坐标系 y 向下，所以 `uy < 0` 表示"略向上"；M4 约 -0.395°、M5 约 -0.224°；
8. **点积**：`a·b = ax·bx + ay·by = |a||b|cos θ`；代码就是"两乘一加"（第 204 行）；
9. **`s = x·ux + y·uy`**：`|u| = 1` 时是有号投影长度，单位 px（第 180、204 行）；
10. **`project_point()` 的再次归一化**：函数不假设调用方守规矩；冻结常量只有 6 位小数，`|U| - 1 ≈ -2.4e-7`、`|U_004| - 1 ≈ -3.4e-7`（第 196～202 行）；
11. **投影的取舍**：正交分解后，垂直分量与 `u` 的点积恒为 0——沿运动方向 1:1 保留，垂直分量在一维信号里不出现（第 6.6 节）；
12. **`s_px` 是坐标，不是位移**：它是沿 `u` 的一维位置；"相对基线的位移"要等 L10 的 `s0`；
13. **M4 的 `U = (0.999976, -0.006894)`**（`src\displacement.py` 第 55 行）与 **M5 的 `U_004 = (0.999992, -0.003913)`**（`src\dynamic_displacement.py` 第 66 行）：两组方向常量都绑定各自的实验；
14. **真实数据验证**：加归一化后，M4 的 1050 行、M5 的 1766 行 `s_px` 与 `(x·ux + y·uy) / |u|` 的最大偏差分别为 `4.974e-4` / `4.998e-4 px`；最小二乘拟合系数与 `U / |U|` 一致到 `1e-7` 量级（第 8 节）；
15. **误差来源是文本舍入**：`s_px` 写 3 位小数（上界 `5e-4 px`）、`x_px` / `y_px` 写 2 位小数；不是算法误差；
16. **L08 → L09 → L10 分工**：尺度 → 方向与一维坐标 → 基线与位移；
17. **六类材料**：真实源码 / 真实项目常数 / 真实数据 / 数学公式 / 教学示例 / 概念伪代码（第 10 节）。

## 13. 易错点

1. **用原始方向向量直接算 `s`（忘记归一化）。** `s = x·ux + y·uy` 只有在 `|u| = 1` 时才是"沿方向的像素距离"；项目里由 `project_point()` 第 196～202 行兜底，但手算/写脚本时必须自己先归一化；
2. **以为"冻结的 `U` 已经是精确的单位向量"。** `|U| = 0.999999763906`、`|U_004| = 0.999999655816`——它们只是"在自检容差内"的单位向量（M4 容差 `1e-4`，M5 容差 `1e-6`）；
3. **手算 `s_px` 与 CSV 差 `2.5e-4` 就以为数据错了。** 先分清两层：① `project_point()` 会再次归一化（不计入会差到 `8e-4~9e-4 px`）；② `s_px` 只写 3 位小数（舍入上界 `5e-4 px`）；
4. **把 `s_px` 当位移。** 它是位置坐标；位移是相对基线的差（L10 的 `ds_px`）；
5. **把方向取反（`P2 → P1`）而不追问约定。** 方向约定写在 docstring 第 149 行与常量注释里；M5 的自检直接用 `U_004[0] > 0` 锁定"ds 增大"的正方向；
6. **把 `ux`、`uy` 与 cos/sin 的关系记反。** 图像坐标系 y 向下：`uy < 0` 表示"向上"，与数学坐标系里的直觉相反（第 5.7 节）；
7. **把点积与逐元素相乘混淆。** 点积的结果是**一个标量**（`x·ux + y·uy`），不是"每个分量各自投影"；`u` 用点积把二维点压成一条数轴的坐标；
8. **以为投影"丢掉了 y 信息"。** y 仍然通过 `uy` 进入 `s`；准确说法是"垂直于 `u` 的分量对 `s` 的贡献为 0"；
9. **以为"削弱垂直分量"= 垂直方向的真实运动不存在。** 垂直方向若真有运动，`s` 也看不到它——这是降维的取舍，要写清楚而不是当成 bug；
10. **把 `px/mm` 与 `mm/px` 乘反。** `ds_mm = ds_px / PX_PER_MM`；用反方向会差约 33 倍（L08 已记录，L09 的复算里同样适用）；
11. **混用 M4 与 M5 的方向常量。** 尺度与方向都绑定各自的拍摄；`src\dynamic_displacement.py` 第 20～23 行从结构上禁止混用；
12. **把教学示例当项目数据。** docstring 里的示例坐标、第 5.6 / 6.6 节的算术例子都不是项目数据；项目数字一律以 `results\` 里的真实行为准；
13. **用"两个标定点的 `s` 之差"验证方向时忘记归一化。** 跳过归一化会得到 M5 的 `608.634444 px`（而不是 `608.634653 px`），差 `2.09e-4 px`；把归一化算进去才会与 `L_pixel` 精确一致；

## 15. 一句话总结

> L08 造好了"尺子"（`px/mm`、`mm/px` 与 M4 / M5 冻结常量），L09 讲清了"沿哪条线量、怎么量"：`compute_scale()`（`src\calibration.py` 第 100～144 行）用 `dx` / `dy` / `pixel_distance = math.hypot(dx, dy)`（第 128～131 行）、`px_per_mm = pixel_distance / real_distance_mm`（第 137 行）与互为倒数的 `mm_per_px`（第 138 行）把"两点 + 真实长度"变成尺度；`unit_direction()`（第 147～173 行）把原始方向向量 `v = P2 - P1`（第 166～168 行）归一化成 `u = (dx/|v|, dy/|v|)`（第 173 行）——因为只有 `|u| = 1`，`s` 的单位才和坐标一样是像素、`ux` / `uy` 才能读作 cos / sin；`project_point()`（第 176～204 行）用**点积** `s = x·ux + y·uy`（第 204 行）把二维像素坐标压成沿尺方向的一维坐标 `s_px`，并且**自己再归一化一次方向**（第 196～202 行）——因为项目里的冻结常量 `U = (0.999976, -0.006894)`（`src\displacement.py` 第 55 行）与 `U_004 = (0.999992, -0.003913)`（`src\dynamic_displacement.py` 第 66 行）都只有 6 位小数，`|U|` / `|U_004|` 与 1 差约 `2e-7`；投影之所以能保留沿运动方向的分量、削弱垂直方向分量，是因为正交分解后垂直分量与 `u` 的点积恒为 0——沿尺移动 1 px，`s` 变 1 px；垂直移动 10 px，`s` 里只漏进不到 `0.07 px`。真实 CSV 逐行复核给出了完整闭环：M4 的 1050 行、M5 的 1766 行 `s_px` 与 `(x·ux + y·uy) / |u|` 的最大偏差分别为 `4.974e-4 px` 与 `4.998e-4 px`，正好落在"写 3 位小数"的舍入上界 `5e-4 px` 之内；最小二乘反推的系数与 `U / |U|` 一致到 `1e-7` 量级——**公式、常量、归一化、数据链四者互相印证**。`s_px` 是坐标不是位移：`s0` 如何选、valid gate 的完整规则、`ds_px` / `ds_mm` 的完整流程，都是 **L10** 的内容，本课只登记名称与位置。
