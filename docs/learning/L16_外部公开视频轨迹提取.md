## 6. 【项目真实源码】ROI：先看哪一小块画面

第 65 行注释："冻结 ROI（右端为开区间）"。第 203 行：

```python
roi = gray_frame[ROI_Y_MIN:ROI_Y_MAX, ROI_X_MIN:ROI_X_MAX]
```

- ROI 范围：x ∈ [690, 780)、y ∈ [380, 760)（第 66–69 行常量，第 578 行打印原文 `ROI：x ∈ [690, 780)   y ∈ [380, 760)`）；
- ROI 尺寸：**宽 90 px × 高 380 px**（780 − 690 = 90；760 − 380 = 380）；
- NumPy 切片是"先行后列"：`[y 起点:y 终点, x 起点:x 终点]`（L03 的知识），所以第一个切片对应 y、第二个对应 x。

**必须说明：输出 CSV 的坐标是整帧坐标。** 暗带是在 ROI 局部坐标系里被找到的，但写入记录前要把 ROI 偏移重新加回去：

- 第 241 行：`"x_px": (band_x_min + band_x_max) / 2.0 + ROI_X_MIN`（加回 `ROI_X_MIN`）；
- 第 243 行：`"y0_px": float(band_start + comp_y + ROI_Y_MIN)`（加回 `ROI_Y_MIN`）。

【概念解释】这就是"局部窗口里算，整帧坐标里报"的标准做法：ROI 只用来缩小搜索范围、排除画面其他区域，不改变输出的坐标口径。

## 7. 【项目真实源码】灰度与阈值：逐像素二值条件

- 第 315 行：`gray_frame = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)` —— 在逐帧循环内把 BGR 帧转成灰度图（`convert` 到 GRAY）；
- 第 316 行：`detection = detect_dark_band(gray_frame)` —— 把灰度帧交给冻结检测函数；
- 第 204 行：`binary = (roi < GRAY_THRESHOLD).astype(np.uint8)`。

【项目真实源码】第 204 行的语义：`roi` 中**灰度低于 120 的像素被设为 1，其余为 0**（先在布尔数组上比较，再 `astype(np.uint8)` 转成 0 / 1 的整数图）。

【概念解释】与 L03 的 Mask 概念联系：**本质都是"逐像素二值条件"**——对每个像素问一句"你满不满足条件？"，满足记 1 / 255，不满足记 0。区别在条件来源：M5 根据颜色判断（HSV 红色区间，`cv2.inRange` 输出 255 / 0），M6 根据亮度判断（灰度 < 120，输出 1 / 0）。M6 这里的 `binary` 就是"暗像素在哪"的逐像素判断表。

## 8. 【项目真实源码】Connected Components：从像素到候选区域

第 205 行：

```python
num_labels, labels, stats, _ = cv2.connectedComponentsWithStats(binary, connectivity=8)
```

**【项目真实源码】必须强调：M6 不使用 `cv2.findContours`。** 对 `src\external_oscillation_tracker.py` 只读检索 `findContours` 为 **0 命中**；该模块用的是连通域分析（`connectedComponentsWithStats`）。

第 210–217 行（逐 label 循环的头部）：

- 循环从 `label_index = 1` 开始（第 210 行）→ **0 号 label 是背景**，不参与候选；
- 第 211–215 行读取连通域的 `comp_x / comp_y / comp_w / comp_h / comp_area`（`cv2.CC_STAT_LEFT / TOP / WIDTH / HEIGHT / AREA`）；

【概念解释】Connected Component（连通域）关心的是"**哪些像素属于同一区域**"：在 8 邻域（`connectivity=8`，上下左右加四个对角都算相邻）的规则下，把所有满足暗条件、又彼此连通的像素聚成一个候选区域，并直接给出这个区域的外接框与面积。M5 的 Contour 更强调"**目标边界**"（从 Mask 找边界点集），是两种不同的区域表示方式：一个以"像素集合 + 统计量"为主，一个以"边界曲线"为主。

## 9. 【项目真实源码】逐行跨度：找"横向、连续、够宽"的暗带

`find_longest_span_run()`（第 172–189 行）的 docstring 说明：在"逐行暗像素跨度"序列里，找**最长连续满足 跨度 ≥ 35 px** 的段（第 174 行）；返回 `(行数, 起始行, 结束行)`，结束行为开区间，没有满足条件的段时返回 `(0, 0, 0)`（第 176 行）。

- 第 182 行：`is_wide = (index < span_count) and (row_spans[index] >= MIN_ROW_SPAN_PX)` → **单行暗像素跨度至少 35 px**；
- 第 183–188 行：维护当前连续段 `run_start`，当连续段结束时与 `best_rows` 比较，取更长的段。

第 219–223 行（在 `detect_dark_band()` 内）：

- 第 219 行：`comp_mask = labels[comp_y:comp_y + comp_h, comp_x:comp_x + comp_w] == label_index` —— 构造"**只属于当前连通域**"的布尔掩膜；
- 第 220 行：`row_spans = comp_mask.sum(axis=1)` —— 逐行统计"该行属于本连通域的暗像素个数"（模块文档第 15–16 行注明：实心暗带时该计数等于水平暗像素跨度）；

【项目真实源码 / 概念解释】这套规则用来识别"**横向、连续、够宽**"的暗带：单行要足够宽（≥ 35 px），并且这种宽度要连续保持若干行（≥ 3 行），才可能是目标暗带，而不是零散噪点或竖向细缝。

【教学示例（非项目数据）】假设某连通域逐行暗像素计数为 `[30, 36, 40, 38, 12]`：以 35 px 为门槛，达标行是第 2–4 行（36 / 40 / 38），连续 3 行 → 刚好达到 `MIN_BAND_ROWS = 3`；第 1 行（30）与第 5 行（12）不达标。此例只用于理解"连续"与"门槛"的关系，不是任何真实帧的数值。

## 17. 【概念解释】本课的工程思想

1. **没有"一套视觉算法打天下"**：同一项目里，M5 用红色 HSV 检测、M6 用灰度暗带检测（第 31–34、85、204 行）。
2. **先找目标最稳定的视觉特征**：在外部视频里选的不是颜色，而是"暗、横向、连续、够宽"的暗带特征（第 13–18 行的冻结规则）。
3. **再把场景先验变成 ROI 和几何规则**：搜索范围收缩到 90 × 380 px 的 ROI（第 65–69、203 行），形状约束变成宽度 / 高度门槛（第 79–82、233–236 行）。
4. **冻结参数**：第 49–51 行明确"M6.2-2B 冻结常量（本模块唯一参数来源）"；第 31–34 行禁止本模块重新设计算法。
5. **用明确 QC 检查检测器**：第 442–549 行的 17 项清单（含信息项）逐条检查表头、行数、帧区间、detected、空值、范围、跳变、候选歧义、时间一致性，以及原始视频 SHA-256 完整性与 `y0_px` 有限性（第 14 节）。
6. **正式分析变量与 QC 变量必须区分**：`y0_px` 是正式位置特征；`x_px`、`bbox_w_px`、`bbox_h_px`、`area_px`、`candidate_count`、`accepted_count` 都是 QC / 诊断信息（第 200–201、240–241、330–331、493–497 行）。
